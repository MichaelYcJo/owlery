**Decisions made while building.** Each is the work's, judged against `frame/design.md` *Scope* items 9 to 11 and *Data & interfaces*, "The steps".

- **The recorder notes six kinds of event** on the pane's hidden textarea, in the capture phase: `keydown`, `keyup`, `compositionstart`, `compositionupdate`, `compositionend` and `input`. `stepsOf` reads `compositionstart` only to know whether an `input` of type `insertText` falls outside a composition, which the steps' table asks.
- **Three rules of `stepsOf` are not in the steps' table.** An `insertText` input whose text is the text of the plain key just pressed is that key's own, and becomes no commit, because the replayed key inserts it again. A release whose press the record does not hold is dropped, and a key still pressed at the record's end is released there, because a person releases a line's Enter after its bytes arrived and the record of the next line begins with that release.
- **A line's record ends 300 ms after its Enter's byte arrived.** `Received.typed` waits for a `0d` among the new bytes, ten minutes at most for one typing, and then that moment for a byte sent after the Enter. The whole run has one hour.
- **The typed run writes the fixture only where every line's typing matched.** The frame says the fixture's change is committed with the release, and a run with a failed line exits 1. `gaps.md` *Not done* says what that costs.
- **`formatFixture` writes the file in the form it stands in**: the steps of one key on one row. A case reads that it returns the committed file's text unchanged, so a typed run's diff shows the lines it changed and nothing else. `JSON.stringify` alone would have put every field of every step on a row of its own.
- **`typedRun` holds `date`, `macos`, `electron`, `xterm` and `replayDiffers`**, the last a list of `{ text, received }` with the replay's bytes in hex. The macOS version is read from `sw_vers -productVersion`.
- **The bar stands at the window's lower edge and lets a click through.** Its text names the line's place, its text and its keys, and says that the terminal shows nothing of what is typed: the receiver's terminal has no echo, so a person sees the composing syllable alone.
- **The file runs as the typed run or as the replayed case, never both.** `describe.runIf` and `describe.skipIf` read `OWLERY_KOREAN_TYPED`, which the script `korean:typed` sets.
- **`readLines` left `korean-pane.ts` for `readFixture`**, which also returns `typedRun`. The test file was its one reader, and `git grep readLines` prints nothing at `0ddacf7`. `frame/design.md` *Removes* does not name it.

**A run that Ctrl-C ends has to stop the daemon in the handler of the signal.** `frame/design.md` scenario 6 asks that the command, stopped at its first line, leaves no process. The daemon is started detached, so the signal does not reach it, and vitest exits at SIGINT without running a `finally` or an `afterAll`.

- `executed`, probe `test_tmp_signal.test.ts`, run once before the code was written and moved to this phase's scratch, `sig/`: a case under the suite's runner started a detached `sleep` and waited. SIGINT sent to the command's process group reached the test process, whose handler ended the `sleep` and wrote its marker 1.5 s later without giving the event loop a turn, and the whole group had exited. The probe started no app.
- So `built-app.ts` gained `endNow`, which asks processes to end, waits and kills without a turn of the event loop, and `BuiltApp.stopNow`, which calls it for the app and the daemon and removes the user data folder. The typed run calls it from handlers of SIGINT, SIGTERM and SIGHUP and from the test process's `exit`.
- `endNow` reads a process as ended where `ps` gives its state as `Z`. The app is the test process's child, and a child that ended is listed until its parent reads it, which a handler that keeps the event loop cannot do. A first writing that asked `process.kill(pid, 0)` would have waited its whole bound for such a child. The case "ends processes at once" pins it.
