# Changelog: the Korean input regression test

Issue #10. A person had typed Korean into the terminal pane once, by hand, and nothing in the repository typed it again, so a change that broke composition in the pane would have been found by the next person who typed.

- **The desktop app's checks type Korean into a terminal pane.** A case of `pnpm run test` builds the app, starts it, opens a shell pane through the "New work item" form, and replays ten lines of Korean composition into the pane through Electron's debugging port. It reads the bytes the pane's process received and fails where a line's bytes are not the UTF-8 of its text followed by Enter. The lines cover a final consonant that moves to the next syllable, a double final consonant that splits, a vowel made of two keys, Space, a digit and a full stop that end a composition, and Backspace inside one.
- **The checks open the app's window while that case runs**, for about nine seconds, on a machine with a display. The app runs with folders of its own under the system's temporary folder, and the case stops the app and its daemon and removes the folders.
- **`OWLERY_BACKGROUND=1` starts the app in the background.** With that value in its environment the app has no Dock icon and no menu bar on macOS, and its window opens without taking the keyboard. The case starts the app that way, so the checks do not take the keys of the person at the machine. Without the variable, or with any other value, the app starts as before. The variable is for a start a test or an agent makes, and no screen of the app names it.
- **`pnpm --filter @owlery/desktop run korean:typed` is the run a person types at each release.** It opens the same pane and shows one line at a time in a bar over the window, with the keys to press. The person types the line with a Korean input source and presses Enter. The run compares the bytes by itself, shows a line once more where they differ, and fails the line at a second difference. It prints a verdict for each line and exits 0 only where every line arrived as typed.
- **The typed run records what the typing produced.** It notes the key, composition and input events of each line, replays them into the pane, and where the replay delivers the line's bytes it writes them into `apps/desktop/test/fixtures/korean-input.json`, which the case replays from then on. A line whose replay differs keeps its steps and is named in the fixture with the bytes the replay gave. The change of that file is committed with the release.
- **Nobody has made the typed run yet.** Every line the case replays is in the order of events its authors assumed, so the case guards the pane's own code and does not yet stand for a macOS input source. The first typed run is owed by the release that closes milestone 1.
- **The roadmap's open decision on how this test runs is settled as both ways**, the replayed case in the checks and the typed run at each release. `docs/roadmap.md` takes that text at the settle after the release.
