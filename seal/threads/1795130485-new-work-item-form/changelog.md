# Changelog: the new work item form

Issue #85. The form refused to create a work item without a title, never showed the branch the title would become, and cut every work item at whatever branch your checkout happened to stand on.

- **The name is optional.** The field is now called "Name" and shows a name Owlery made, two words such as `amber-heron`, as its placeholder. Leave the field empty and the work item, its branch and its worktree's folder take that name.
- **A name with no letter or digit of `a-z0-9` keeps its own title.** A work item named in Korean alone is listed under the name you typed, and its branch and folder take the generated name. Such a work item used to get the branch `owlery/work-item`.
- **The form shows the branch and the folder before you create.** Under the name it shows the branch the work item will get, such as `owlery/fix-login`, and its worktree's folder, and both follow the name as you type. Where the name is taken, it shows the name with the number Owlery appends, such as `owlery/fix-login-2`. A folder that is no git repository is said there too.
- **You choose where the work item starts.** A new menu, "Starts from", lists the repository's local branches and its remotes' branches. The branches Owlery made for your other work items are among the local ones. A local branch that is only another name for a branch, such as an alias `main` of `master`, is not listed, and the branch it names is.
- **The default start is the repository's default branch, and no longer the branch your checkout stands on.** In a repository with a remote that is the remote's default branch, such as `origin/main`. In a repository without one it is the local branch `init.defaultBranch` names, then `main`, then `master`, then the checkout's branch. To start from your checkout's branch, choose it in the menu, where it is the first of the local branches.
- **A remote's branch is fetched before a work item starts from it** (#96). A work item that starts from `origin/main` starts where the remote has that branch, or, where the fetch fails, where your last fetch left it. It does not hold commits you made on the local `main` and did not push, which you get by choosing `main`.
- **A work item's branch has no upstream**, whatever it starts from.
- **A work item that starts from a remote's branch counts its commits against that branch.** Its facts read "origin/main · 6 ahead", and the count moves when a fetch moves the branch.
- **After an update, the form shows no branch, and its menu "Starts from" stays empty, until Owlery's background process restarts.** A process started by the build before this one answers no plan. A work item created against it starts from the checkout's commit, as before. One left without a name gets the branch `owlery/work-item`, the folder `work-item` and no title there, so give a work item a name until that process restarts.
- **For a client of the daemon:** `createWorkItem` takes two optional fields, `name` and `base`, and its `title` may be empty. A new message `planWorkItem` is answered with `workItemPlan`, which carries the branch and the folder a creation would get, the repository's bases in `localBases` and `remoteBases`, and `defaultBase`. A plan that fails is answered with `error` under the plan's `requestId`. `WorkItem.baseBranch` can name a remote's branch.
