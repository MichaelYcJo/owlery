# Changelog: a new work item makes a worktree, and its branch is picked or made later

Issue #217. Each new work item cut a branch named after the random name the form offered, whether or not any work landed on it, so a repository gained a branch named after nothing at each creation. A work item also could not start on a branch the repository already had.

- **A new work item adds no branch.** With no branch picked, its worktree stands detached at the base the form names, and the repository's branches are what they were before.
- **The first commit or a rename makes the branch.** Owlery makes the branch `owlery/<the work item's name>` at the first commit in the worktree, at its next read of the work item, which comes within a few seconds while Owlery's window is open. A rename makes it at once, from the new name: the rename dialog says "The rename makes the branch <name>." with its choice taken. A name already taken gets `-2`, `-3` and so on. A branch the worktree's agent made or checked out itself before then, as with `git switch -c`, becomes the work item's and keeps its name.
- **The form picks a branch to check out.** A field "Branch" under "Starts from" offers "No branch yet" first, then the repository's local branches and its remotes' branches. A local branch is checked out as it stands. A remote's branch is checked out as a local branch of its name that tracks it, or as the local branch of that name where one stands. A branch another worktree has checked out, the main checkout among them, is offered disabled, with that worktree's folder in its label, and a creation that names one is refused. Under the name, the form says what the creation does of the branch.
- **A delete removes only the branch Owlery made.** A branch the person picked, and one the worktree took up by itself, stays, and the delete's dialog says so. Owlery does not rename such a branch either.
- **A work item with no branch yet says so.** Its line, its preview and its view's head say "No branch yet". Its menu holds no "Copy branch name", and its view shows no seal and no pull request section. A chain does not start on it, and the chain command in its pane says that the branch comes with the first commit. Its counts of commits ahead and behind are read from the worktree.
- **Owlery keeps whether it made each work item's branch.** `repositories.json` gains `ownsBranch` on each work item, and a work item's `branch` may be `null` there. A work item stored by an earlier build is read as one whose branch Owlery made, so nothing is migrated. A daemon of an earlier build refuses a `repositories.json` that holds a work item with no branch, which matters only where a person goes back to an earlier build.
- **A window of this build attached to a daemon of an earlier build** shows no "Branch" field and the plan's branch as before, since that daemon still cuts a branch at each creation.
