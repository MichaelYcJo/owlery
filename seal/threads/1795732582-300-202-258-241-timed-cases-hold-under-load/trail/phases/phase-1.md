**The frame holds, with two departures below.** `frame/design.md` *Scope* item 1 was built as stated: `pnpm patch-commit` under pnpm 10.33.0 wrote `pnpm.patchedDependencies` with the one key `node-pty@1.1.0` into the root `package.json`, the patch to `patches/node-pty@1.1.0.patch`, and its hash into `pnpm-lock.yaml`. **The leaked slave is named "(revoked)", not `/dev/ttys…`.** *Scope* item 2 asks the case to read descriptors that name `/dev/ptmx` or `/dev/ttys…`. A probe (`test_tmp_all_fds.cjs` in the crafter's scratch, run once under Electron 45.3.3 as Node against the unpatched build) listed every descriptor of the process around one start: while the process ran, the parent held two `/dev/ptmx` descriptors and the slave `/dev/ttys023`; after it ended, one `/dev/ptmx` and the slave's descriptor stayed, and `lsof` named the slave `(revoked)`, since macOS revokes a slave once its master closes. A case reading the two device names alone would pass with the slave left open. So the case's helper `terminalDescriptors` also counts a descriptor `lsof` names `(revoked)`. Judged against `frame/design.md` *User scenarios & acceptance*, first row, which asks that no descriptor be left that names a pseudo-terminal.

**The patch is bounded where node-pty 1.2.0-beta.18's loop is not.** The beta closes `low_fds[0]` to `low_fds[count]`. `count` reaches 3 where all three `posix_openpt` calls of the spare loop return -1, which happens at the machine's limit, and `low_fds[3]` is then read past the array. The patch closes `low_fds[i]` for `i` from 0 to `count` while `i < 3`, and skips a -1. It closes `slave` without a guard, since every path to `done:` has opened it in 1.1.0's order. Judged against `frame/design.md` *Scope* item 1, which names the closes and not the loop's form. The paths that return before `done:` still leak, and `gaps.md` *Not done* says why.

**A start at the limit throws; it does not return silently.** `frame/design.md` *Grounding*, the row "#300, what was not reproduced", reads that `pty_posix_spawn` returns with `*master == -1` and no error set. So a pane started at the limit fails with that error.
