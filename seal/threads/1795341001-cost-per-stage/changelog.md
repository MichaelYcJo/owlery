# Changelog: the daemon keeps what each stage of a work item cost

Issue #45. Owlery's background process, the daemon, kept the cost of a headless session only while the session stayed in its memory, at most the last 50 that ended, and kept it as one number, with no tokens and nothing to say whether it was a charge. So nothing could be set beside what a review round caught.

- **Each headless session that ends gets one entry in a cost ledger.** The daemon appends the entry to `ledger.jsonl` in its run folder, readable by you alone, when the session ends: at its result, at an error result, at an exit with no result, at a stop at its limit of 60 minutes or at a request, and at the daemon's own stop. An entry names the work item, its repository's folder and its branch as they stood when the session was asked, the role and the stage, or none for a session asked with no role, when the session started and ended on the daemon's clock, how it ended, what stopped it, and what it used. A stage's duration is its end less its start.
- **What a session used is its cost in US dollars and, for each model, the input tokens, the output tokens, the tokens read from the cache, the tokens written to it and that model's cost.** A count the agent did not report is empty, not zero. The Claude adapter reads them from the result Claude Code prints at the end of a turn.
- **Every cost says whether it is a value converted at API prices.** Under a subscription login Claude Code prices a turn at its list prices, and that is no charge. The adapter takes a cost as what the account is billed only where the session's login names an API key: Claude Code's `apiKeySource` is `ANTHROPIC_API_KEY`, `apiKeyHelper` or `/login managed key`. Under every other login, and where the login cannot be read, the cost is marked as converted. Whether a key login's cost equals its bill has not been compared yet: issue #140 runs it with an API key login.
- **A stage that was stopped has an entry with no usage.** The daemon takes nothing from an agent after it stops it, at its limit, at a request or at its own stop. Whether Claude Code reports what it used after such a stop is issue #141's. A session whose agent did not start gets no entry, because nothing ran. A daemon that crashes writes no entry for the stage it cut.
- **The ledger outlives the daemon, and nothing of it is committed.** A daemon that starts on the same run folder reads the entries the one before it wrote. No file of the ledger is written in a repository or a worktree.
- **No delete takes an entry out.** Deleting or removing a work item leaves its entries in the file, because the public ledger covers work items after they are merged and deleted (issue #76).
- **A line of the file the daemon cannot read stays in the file, and is counted.** A line a crash or a failed append cut is left as it is, and the next entry starts on a line of its own. Where an entry cannot be appended, the daemon's log says why, and the entry is kept in memory, given in every read and written before the next entry.
- **Nothing in the window shows a cost yet.** The back of the seal draws the ledger beside each round's catch (issue #47).
- **For a client of the daemon:** a headless session carries `usage` in place of `costUsd`: `costUsd`, `converted` and `models`, each model with `model`, `inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens` and `costUsd`, or null until the result and where the result carried none. A new message `readLedger`, with `requestId` and `workItemId`, is answered with `ledger`: the work item's `entries` since its creation, in the order their stages ended, and `unread`, the count of the file's lines that are no entry. An archived work item is answered as any other, and an id the daemon lists no work item under with `error` `no work item <id>`. An entry carries `workItemId`, `repo`, `branch`, `stage` (a role and its stage, `{ "role": null, "stage": "gate" }` for the broad gate, which no stage writes yet (issue #42), or null), `startedAt`, `endedAt`, `state` (`finished` or `failed`), `stopped` (`limit`, `request`, `daemon` or null) and `usage`. A daemon of an earlier build answers `readLedger` with nothing, and sends `costUsd` and no `usage`.
