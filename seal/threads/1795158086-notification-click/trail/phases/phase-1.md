**Decisions made while building, each with its grounds.**

- *The handler does not wait for the main process before it opens the view.* It calls `window.owlery.comeForward()` and opens the view in the same turn. A view drawn after the answer would show the old screen for a moment in a window that is already in front. Judged against `frame/design.md` *Data & interfaces*, "The handler calls `window.owlery.comeForward()` and then `openView`", which fixes the order of the two calls and not a wait.
- *The session a click answers for is the one of the `inbox` that raised the notification.* A session's `id` and `workItemId` do not change while it is listed (`apps/desktop/src/shared/protocol.ts`, `SessionInfo`). What is read at the click is the window's two lists, as *Scope* items 3 and 4 ask.
- *`enterView` notes the pane with `broughtToFront`, the function a press of a tab calls.* `showView` then finds that pane first among the panes that were in front, and gives it the keyboard as it does for any pane that comes in front. With the form open the keyboard stays in the form, because the form is a modal dialog and the page behind it takes no focus. Judged against *Scope* items 4 and 6.
- *Scenario 3 feeds `UserPromptSubmit` while it sets up, before Beta exists.* `frame/design.md` scenario 3 feeds both events with Beta's view in front. The daemon lists a silent Claude Code pane as waiting ten seconds after its start (`apps/desktop/src/daemon/daemon.ts`, `silentStartOver`), and by then the shell pane is in front of Alpha's view, so that change would raise a notification of its own. The case feeds the first event right after Alpha is created, while Alpha's agent pane is on the stage of a focused window and no notification is raised, and waits for the strip to read `working`. `PermissionRequest` is fed with Beta's view in front, as the scenario states. The first test asserts that the recorder is empty before it.
- *The case reads the agent pane's id from the daemon as a second client.* The page shows no pane id. The case reads `run/daemon.json` of the started app's own user data folder, says `hello`, and takes the Claude Code session from `ready`.
- *The case feeds the hook socket with `/usr/bin/nc` from inside the run folder,* by the socket's file name. That is how the hook's own command reaches it (`apps/desktop/src/daemon/hooks.ts`, `RELAY`), and a temporary folder's path can pass the 104 bytes macOS allows a socket path.
- *The second test types "Gamma" into the form's name field before the click,* so "with what it holds" in *Scope* item 6 is asserted on the name and on the repository folder.
