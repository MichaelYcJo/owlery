# Changelog: a daemon that cannot read its repositories file keeps it

Issue #257. A daemon that could not read `repositories.json` started with no repositories and wrote its first change over the file. A person who ran an earlier build after a later one, whose file that build cannot read, lost every repository and work item from Owlery's lists, though the worktrees, the branches and the records stayed on disk.

- **A daemon that cannot read `repositories.json` keeps the file aside.** A file it cannot open, one that holds no JSON, and one whose shape its build does not read, such as a file a later build wrote, is renamed in Owlery's run folder to `repositories-unread-<UTC time>.json`, as `repositories-unread-20261126T123005Z.json`. Where that name stands, `-2`, `-3` and on are added, so no file kept earlier is replaced. Nothing in the kept file is changed. The daemon starts with no repositories and writes a new `repositories.json`, holding none, beside the kept file at once, so a daemon stopped before any change leaves a list its next start reads.
- **A work item made after the refusal takes none of the kept file's ids.** Where the kept file states the next ids it would give, as a file a later build wrote does, the daemon goes on from them, so the output of a broad gate and the record times Owlery keeps under a kept work item's id are not dropped by a new work item. A file that states no next ids, such as one that holds no JSON, gives ids from 1 again.
- **The status line says where the file was kept**, for example: "Owlery could not read its list of repositories, so it kept the file as …/repositories-unread-20261126T123005Z.json and started with none. Nothing in that file was changed." It stands while that daemon runs, in every window that connects to it. The window's own notice and the notice of a daemon of another build stand before it, and the notice of the installed Claude Code after it.
- **Where the file cannot be moved, nothing writes over it.** The file stays as it is, the daemon keeps its repositories in memory alone until it stops, and the status line says: "Owlery could not read its list of repositories at …/repositories.json, nor move it aside. The file stays as it is, and no change to the repositories is kept once the daemon stops."
- **A kept file comes back by hand.** Under a build that reads it, stop the daemon with "Quit Owlery Completely…" and rename the kept file to `repositories.json`. That replaces the `repositories.json` the refusing daemon wrote, with every repository added under it.
- **Builds before this one still write over such a file.** `v0.0.5` and earlier start with no repositories and write over a file they cannot read at their first change, so a person who runs one copies `repositories.json` aside first.
