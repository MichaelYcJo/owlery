## Operational impact

- **A connected repository has to move.** After an update to an app that holds this work, a repository with `seal/` and `owlery-seal.yml` reads as one whose records are in the earlier form: its row says so, no chain starts there, and the dialog "Records and check" offers the one commit. A work item's branch that held records before the move runs the chain command's `migrate` once.
- **A required check has to be named again.** A repository whose rules require the check `seal` requires a check that is no longer posted. An administrator requires `inspection` in its place, and the dialog and `README.md` say so. Owlery changes no setting of a repository.
- **An open pull request's body is rewritten by the chain.** Until the chain's `body` or the daemon's pull request stage writes the sections with the new markers, the check refuses the body's section.
- **The migration needs a tag that holds the renamed check.** The workflow the migration writes clones `pr-check/` at the tag of the app's version, or at the branch `release/v<version>` until the tag exists. So this pull request carries the release's version move. Phase 5's commit that adds `changelog.md` carries it, and reads and writes the version in `apps/desktop/package.json`. The number is the owner's, as `docs/roadmap.md` *Releases and the tracker* states, and `frame/questions.md` Q1 holds it. An app built from this branch before that tag or branch stands writes a workflow that fetches nothing, which issue #277 describes.
- **This repository does not move.** Its `seal/` root, its `owlery-seal.yml` and that file's pin stay as they are. The check its pull requests run is the one its workflow pins, so the renamed `pr-check/` on this branch judges no pull request of this repository.
- **The settle wrapper loses `--apply`.** A release of this repository is settled with the plugin's command, run directly. `docs/roadmap.md` *Releases and the tracker* is rewritten to say so in phase 5.
- **No new dependency and no new environment variable.** The chain command gains the subcommand `migrate` and renames `seal` to `inspect`, so a pane's conversation that began under an earlier build opens `skills/inspection/SKILL.md` again before its next step.
