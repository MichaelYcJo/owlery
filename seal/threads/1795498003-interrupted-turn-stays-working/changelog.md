# Changelog: an interrupted turn leaves its session waiting for you

Issue #182. When you pressed Esc in a Claude Code pane to interrupt a turn, the pane kept saying "Working". Claude Code sends no hook event at an interruption, and Owlery moved a session out of "Working" only at a hook event. So the session stayed "Working" while Claude Code asked what to do instead. A chain could not start in its work item, a word you gave was not committed, and the Mac was held awake.

- **A turn you interrupt leaves its session waiting for you.** The pane is listed as "Needs you", with the text "The turn was interrupted, and the agent waits for what to do next.", no tool and no question. This holds for a reply you stop while Claude writes it and for a tool call you stop.
- **Owlery reads the interruption from Claude Code's session log.** Claude Code writes an interruption into the session log as an entry of yours whose text is `[Request interrupted by user]` or `[Request interrupted by user for tool use]`. Every hook event names the log's file. The daemon watches that file only while the pane is working, reads the lines added to it, and keeps none of them. It sends no window the log's path or any of its lines. An entry of a subagent's, and one written because a message you sent cut the turn, is no interruption. A line longer than 16 KB is skipped unread.
- **Where the log cannot be read, the hook events decide, as before.** Where the log does not stand 10 seconds after the event that names it, or cannot be watched or read, the session's state is what its hook events say. The daemon's log says so once for the pane.
- **An end of the interrupted tool call that arrives later does not make the session "Working" again.** Your next prompt does, and the turn's end makes it "Finished", as before.
- **Everything that waited for the session to stop working stops waiting.** A word you give is committed, with any word left while the session worked. The Mac is no longer held awake for the pane. The daemon's own chain is no longer refused a start in the work item for that session. Nothing in the window starts that chain in this release, since "Get a seal" is gone (#181), so you meet this only once release 0.0.5 hands an issue over (#55).
- **What this release does not cover.** A turn that ends in an API error still leaves its session "Working": Claude Code sends `StopFailure` there, and Owlery does not listen to it yet (#188). No recording shows an Esc while a command runs, or an Esc during a new pane's first reply. The owner's walk of release 0.0.3 (#184) presses Esc in both.
- **For a client of the daemon:** an `agent` message's `event` can be `interrupted`, which carries no tool. A window of an earlier build reads nothing from it.
