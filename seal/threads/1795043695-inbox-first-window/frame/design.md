|---|---|
| `docs/product.md` *Foundation: the inbox, the AgenticSeal process and the back of the seal, with terminals on call*, first paragraph | The app opens on the inbox and not on a pane of terminals. | `docs/architecture.md` *Overall layout*, "Agent state is judged from events, never guessed from what the terminal screen prints" | The line, the preview, the view and the summary screen read the state the daemon keeps, through the function that already gives the inbox line |
| `docs/architecture.md` *The phone: the terminal session as a chat*, "the daemon's WebSocket protocol is not fitted only to the desktop UI, and no state lives on the UI side" | The protocol does not change for the window's layout. Which screen is in front, which line is selected, what is typed in the search field and which repository is folded are the window's own and are kept nowhere. When the person last looked is kept across loads, so it is state: the daemon keeps it, in a message and a field that name no desktop screen, and the window keeps none (*Scope* item 18). | `docs/architecture.md` *Memory design*, rows 1 and 3 | One window, so the four screens are four states of one page. A terminal screen only for a visible pane is issue #9's measurement, and this work makes none at start (*Scope* item 6) |
| `docs/product.md` *What we deliberately don't do*, "We do not build an IDE, a kanban board or a built-in browser" | The inbox is a list of lines in groups, one under another, and not a board of columns |
| `docs/name.md` *What to keep in mind* and `docs/architecture.md` *License and code from other projects*, "Other products' names and logos are not used" | The look borrows no image of the Hogwarts owlery, and no name, logo or copied screen of Orca, Paseo or another product |

A work item matches where what is typed stands, in any case of letters, in its title, its branch or its repository's name. The letters that match are marked in the title and in the branch, and the field says how many match, as in "3 of 10". The list's head says so in words, as in "3 of 10 work items match "sess" in title, branch or repository". Escape in the field empties it and returns the focus to the list.
    - The filter is one state or all of them. Its control opens the choices: "All", and the four headings of item 2. It stands in the sidebar's head and in the list's head and both show the one filter.
    - A search or a filter that leaves no work item says "No work item matches." in the list. A repository none of whose work items match is left out of the sidebar.
    - What is typed and what is chosen are the window's own state, empty and "All" at load.
22. **The history screen** is the inbox screen's list and preview over the work items whose agent finished: the lines whose state is `finished`, newest first by when the state began, with no group's heading. The inbox keeps its "Finished" group as well: nothing leaves the inbox for the history before a work item can be closed, merged or removed, which is milestone 4's (`frame/questions.md` Q9). With no such work item the list says "Nothing has finished yet."
23. **The daemon reads and sends what the lines, the preview and the view newly say.** It is the part of issue #27 the daemon can read from git and from the events it already receives. No new field or value names a vendor.
    - A session carries `stateSince`, the daemon's clock when the session entered its present state, or `null` where it has no state.
    - A session carries `stateText` and `stateTool`: the text and the tool's name that the event which began the state carried, each `null` where the event carried none. The function that reads them from an agent's own event stands beside the map of that agent's events, in `src/daemon/agent-events.ts`, and for Claude Code it reads `tool_name` of a `PermissionRequest`, `last_assistant_message` of a `Stop`, and `message` of a `Notification` where that is text (`frame/questions.md` Q11). The daemon keeps 2000 characters of a text at most. Both are `null` again once the state changes.
    - The window says a session's text as it is, and for a session that waits with a tool's name and no text, "Asks to use <the tool's name>".
    - A work item carries `repoName`, the last part of its repository's folder, and `baseBranch`, the name of the branch the repository's `HEAD` was on when the work item's branch was cut, or `null` where `HEAD` was on no branch and for a work item made before this was recorded.
    - A work item carries `commits`, its new commits newest first, 20 at most, each with a short hash, a subject, the commit's time and its lines added and removed; and `changes`, the files the branch changed since its base commit, 50 at most, each with a path and its lines added and removed, beside the count of all the files and the sums of the lines. A count of lines git gives none for, as for a binary file, is `null`. Both are `null` where the daemon has read none. `newCommits` stays the count of all.
    - The daemon reads a work item's commits and changes when its branch's head is another commit than the one it last read them at, in the read of the counts: at a hello, under the wait of item 18, and at each timed read. The look of item 18 holds work items as they are sent, these fields among them, and a look a build before this one wrote reads as no look.
    - The age the window says of a time is worked out in the window from its own clock, in the words `lastHere` uses: minutes, hours and minutes, or days.
24. **Two themes, and a way to switch.**
    - The themes are `night-desk` and `letter`, the two blocks of item 13. The page's `html` carries the one in use as `data-theme`.
    - A person chooses "Night desk", "Letter" or "Match the system" from a control at the sidebar's foot. "Match the system" is Night desk under the system's dark appearance and Letter under its light one, and follows the system while the window is open. The first run is Night desk (`frame/questions.md` Q7).
    - The choice is kept by the app's main process in a file of its own under the app's user data folder, and given to the page at its load, so a window opens in the theme it was left in, on that theme's ground. The daemon does not learn of it (`frame/questions.md` Q8).
    - A change of theme redraws nothing but the colours, the typefaces, the texture, the radii and the seal's light: no element is added, removed or moved, and each open terminal takes the new theme's colours.
