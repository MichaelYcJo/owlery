## Not done

- **An exited pane the window holds no terminal for cannot be closed from the window.** `paneTabs` gives it no tab (`frame/design.md` *Scope* item 5), so after a reload nothing in the window sends its `close`. The daemon lists it until the daemon exits. The frame names the tabs and not what removes such a session.
- **A pane's process starts at a size that is not its terminal's.** A work item created from the inbox screen starts its pane at 80 by 24, and the first pane of a view started from a button does the same. The terminal sends its fitted size when it is made, a moment later. A program that prints at start may wrap its first lines at the wrong width. Measuring the stage without a terminal was within reach and adds a second way to size a pane; `trail/phases/phase-1.md` gives the grounds.
- **A pane this window started is replayed to it.** Every terminal attaches, so the daemon sends the pane's output so far once more, in the replay. For a new pane that is a few bytes.
- **A process's exit that arrives before the replay is drawn above it.** The window writes the "process exited" line when `exit` arrives, and the guard holds back `output` alone.
- **Each `inbox` redraws the lines, the preview's lists, a view's right column, the tabs and the sidebar's repositories whole.** The keyboard's place on a line, a tab or a sidebar's work item is lost at the next message; the selected line is kept by its id, and what is typed in the search field stays. `frame/plan.md` *Technical context* names it as the chosen approach's cost.
- **A headless answer that arrives while the inbox screen is in front shows nowhere** until its work item's view is opened (`frame/plan.md` *Technical context*). The inbox line says nothing of a headless session (*Scope* item 16).
- **No key returns to the inbox from a view.** The control is the sidebar's "Inbox". The frame names no shortcut for it. J and K act on the inbox screen and the history screen, and Enter on those two and on the summary screen.
- **Not every measure of the page is a custom property.** Every colour, typeface, radius and shadow is one, in the theme's block, and so are the scale of spaces, the sizes of the type and the widths and heights the layout rests on, in the page's own. A measure one rule alone uses stays literal in that rule, such as the 18 pixels at the sides of a list's head. A property per single use was within reach and would name a value nothing else reads.
- **A colour written as a name is not held out of the page by a case.** `test/themes.test.ts` reads hexadecimal numbers and colour functions. The names are a list no case could close; the page uses none today.
- **A transition runs as the pointer comes over a control and not as it leaves.** The rule stands in the pointer's state alone, so that a move of the selection by a key changes at once (`frame/design.md` *Scope* item 13).
- **The form remembers the kind last chosen** for the life of the page, as it did before this work, and preselects the state-reporting kind only at the first opening.
- **A look is written to the disk at every `looked`, inside the daemon's loop.** The write is the list of work items' own: a partial file, then a rename, both synchronous. A window that loses focus many times a minute writes as often. Writing only where the lists changed since the last look was within reach and would leave the look's time stale, which the summary screen says in words (*Scope* item 19).
- **A look is never removed.** No message clears it, and `last-look.json` stays in the run folder with the work items and the sessions of its moment, sessions that ended long ago among them. The frame names one record that a later look replaces, and nothing that ends it.
- **The look holds no headless session.** It is the two lists an `inbox` carries (`frame/design.md` *Scope* item 18), so an answer that arrived while the person was away is no change the summary can name.
- **A file that is not a look is not reported.** The daemon starts with no look, as it starts with no work item where `work-items.json` is not a list, and the next `looked` writes over the file. One entry that is not a session or a work item drops the whole look. Keeping the entries that read was within reach and would hand the summary a look that is missing a work item, which reads as "New since you were last here."
- **The first lines of `README.md` still say "There is no code yet".** The README's opening is issue #21's (`frame/design.md` *Scope* item 16).
- **A read of the counts that never ends stops every later read, and every hello then waits the 500 milliseconds.** One read runs at a time, and a hello joins the read under way. `git` is run with no time limit (`worktrees.ts#git`), as before this work, so a `git rev-list` that hangs holds the one read for the daemon's life. A time limit on git was within reach and changes what a count of `null` means for every work item, which neither issue asks for.
- **The daemon handles nothing a client sent where the client left before its `ready`.** A `looked` or a `start` sent in the wait is dropped with the connection. Before this work a message was handled as it arrived. `trail/phases/phase-4.md` gives the grounds.
- **The summary screen says the changes of this load at every opening.** They are worked out at `ready`, so the screen the sidebar's "Summary" opens an hour later names no change an `inbox` brought since, and a state that moved since still stands in a line's sentence. The next ones come at the next load (`frame/questions.md` Q4's default).
- **A work item made after the load has a plain title** where a look is recorded, like one that did not change: the marks are the changes worked out at `ready`.
- **The sentence of when the person was last here, and every age of a state, a commit and a work item's start, is worked out when its part is drawn,** at `ready`, at each `inbox` and when a screen comes in front, and does not count on by itself. A window left open says the ages of its last redraw. A redraw every minute was within reach and takes the keyboard's place on a line with it, as each `inbox` does.
- **A log or a diff that git failed to give is not asked for again until the branch's head moves.** The daemon keeps the head it read at with what it read, `null` included.
