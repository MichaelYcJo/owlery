# Changelog: repositories, and the menus of a work item and of a repository

Issue #93. A work item could not be renamed, archived or deleted. A repository stood in the sidebar only while it had a work item, and could not be removed. Neither had a menu.

- **Owlery keeps repositories.** The sidebar lists every repository you added, one with no work item among them. A repository's row holds a "+" button, which opens the "New work item" form on that repository, and a "…" button, which opens its menu. To add a repository without a work item, check "Register the repository only" in the "New work item" form. The sidebar's separate button for adding a repository is gone.
- **A work item and a repository each have a menu.** Press the right button, or press with the Control key, on a work item's line or on a repository's row. From the keyboard, press M, or F10 with Shift, on the line or the row the keyboard is on, or for the selected line of a list. The arrows move through the menu, Enter presses an item, and Escape closes it. Every item says what it does when the pointer rests on it, and so does every button that shows an icon alone.
- **Rename.** A work item takes a new name in a dialog. The dialog offers "Rename the branch too" only where the branch was never pushed: it has no upstream, and no remote holds a branch of its name. The worktree's folder keeps its name.
- **Open in, and copy.** The menu opens the folder in Finder, and in each editor and terminal Owlery finds installed among Visual Studio Code, Cursor, Zed, Sublime Text, Xcode, Terminal, iTerm, Ghostty and Warp. It copies the folder's path, and a work item's branch name.
- **Pin and mute.** A pinned work item stands first in its list: in the sidebar, in its state's part of the inbox, and in the history. A muted work item raises no notification, and its line still shows its state.
- **Archive and restore.** An archive takes a work item off the lists and changes nothing on disk: the worktree's folder and the branch stay. Where sessions of the work item are running, a dialog names them first, and the archive ends them. "Show archived work items" on a repository's menu lists them, and Restore brings one back.
- **Delete.** A delete removes a work item's worktree and its local branch. Before it runs, a dialog names what would go: the branch, the folder, each commit no other branch, no remote's branch and no tag holds, each file with a change that is not committed, each untracked file, and the files git ignores, such as `.env`. Where a commit, an uncommitted change or an untracked file would be lost, "Delete" stays off until you check "Force delete". Ignored files are named and go with the folder without the force. Where something arrives after the dialog read it, the delete is refused and the dialog reads again. Nothing on a remote is removed.
- **A commit counts as held where your clone last saw it.** A commit that a remote's branch held at your last fetch is not named as lost, though the branch was deleted on the remote since.
- **A repository's menu** holds its settings (the name the sidebar shows, and the branch its new work items start from), an icon of one character, its archived work items, a new group, the items that open and copy its folder, "Hide from sidebar" and "Remove". A hidden repository's work items stay in the inbox, and a button under the repositories lists the hidden ones.
- **Removing a repository removes nothing on disk unless you choose it.** The dialog names each work item and each running session. "Also delete the work items' worktrees and local branches" deletes each work item as a delete does, with what each would lose named under it. Where one delete is refused, the removal stops there: the work items deleted before it are gone, and the repository and the others stay. "Also move the repository's folder to the Trash" moves the folder whole. It can be chosen where the repository holds no work item, or where the first choice is checked, because a worktree stops working once its repository's folder has moved.
- **Groups.** "New group" on a repository's menu makes a group under a name. The sidebar lists a repository's ungrouped work items first, and then each group under a heading of its name. "Move to" and "Move out of" on a work item's menu move it. The inbox and the history do not show groups, and a group cannot be renamed or removed yet.
- **After an update, Owlery keeps its list in a new file.** The first start reads the work items the build before kept, and writes `repositories.json` at the first change. `work-items.json` stays as it was, so an earlier build started later lists the work items of the day of the update.
- **A background process the build before started lists no repository.** While one is still alive, the status line says that Owlery's background process is from another build and points at "Restart Daemon…" (#101), and the inbox lists the work items as before.
- **For a client of the daemon:** `ready` and `inbox` carry `repositories` and `archived`, and `workItems` no longer holds an archived work item. A `WorkItem` gains `repoId`, `pinned`, `muted`, `groupId` and `archivedAt`. The new requests are `addRepository`, `setRepository`, `removeRepository`, `addGroup`, `setWorkItem`, `planRename`, `renameWorkItem`, `archiveWorkItem`, `restoreWorkItem`, `readLoss` and `deleteWorkItem`. Each is answered with `done`, but `planRename` with `renamePlan` and `readLoss` with `workItemLoss`, and a request that fails with `error`.
