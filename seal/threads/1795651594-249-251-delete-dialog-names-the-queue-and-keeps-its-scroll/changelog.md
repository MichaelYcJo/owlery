# Changelog: the delete dialog names the queue and keeps its scroll

Issues #249 and #251. The dialog that asks before a work item is deleted listed a session that waits for the machine under "Running sessions that end", though such a session has not started and only leaves the queue. The dialog before an archive, the repository's removal dialog and the dialog that asks before the daemon ends did the same. And while any of these dialogs stood open, each message of Owlery's background process drew its lists anew, so a long list that the person had scrolled jumped back to its top, and the tooltip under the pointer closed.

- **A session that waits for the machine stands in a section of its own.** "Running sessions that end" lists each open pane and each session that works. "Sessions waiting for the machine that leave the queue" lists each session that waits under the cap on agents. A section stands only where it holds a session.
- **Each dialog that names the sessions an act ends names them in the same two sections.** These are the delete dialog, the dialog before an archive, the repository's removal dialog and the dialog of "Restart Daemon…" and "Quit Owlery Completely…". An archive of a work item whose only session waits still asks first.
- **What the dialogs end does not change.** A confirmed delete, archive or removal still ends the sessions that run and takes the sessions that wait out of the queue, both by name.
- **A list keeps its place while the dialog is open.** The delete dialog and the repository's removal dialog draw a list again only where what it names changed. A list scrolled past its top stays where it was, and the row under the pointer keeps its tooltip, when the background process sends its lists or when "Force delete" is checked. The session lists and the removal dialog's list of work items stay in place the same way.
- **For a contributor:** `pnpm run screenshots` now waits until the delete dialog lists the scene's shell pane under "Running sessions that end" and its session that waits under "Sessions waiting for the machine that leave the queue", so `<theme>-<appearance>-delete.png` shows both sections.
