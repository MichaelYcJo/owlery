# Changelog: a failed headless session says why, and a run that never ends is stopped

Issue #26. A question asked in a work item's "Ask" section runs as a headless session: Claude Code answers it with no terminal. A session whose CLI crashed said only "the session exited with code 1 and gave no result", because what the CLI printed on its error stream was thrown away. A CLI that never finished kept its session working until Owlery's background process, the daemon, exited, and nothing in the window could stop it. The daemon also kept every session it ever ran.

- **A failed session shows what its CLI printed.** Under the error, the line shows the last 2,000 characters the CLI printed on its error stream, with its line breaks kept. A CLI that does not know an option, for one, prints `error: unknown option '--no-such-option'` there and nothing else. A failure the CLI reports as its result, such as no login, still shows the CLI's own text as the error.
- **A run ends after 60 minutes.** The limit counts from the start, whether the run prints or not. A session still working then is stopped and shows "the session reached its time limit and was stopped".
- **"Stop" stops a run.** The line of a working session has a "Stop" button. A press stops the run, and the line then shows "the session was stopped at a request before it finished".
- **A CLI that ignores the stop is killed 2 seconds later, and so is what it started.** Owlery signals the CLI's whole process group, so a child process the CLI started receives the stop while the CLI runs, and the kill with the CLI where the CLI ignored the stop.
- **Quitting the daemon and deleting a work item wait for the runs they stop.** Each waits up to about 2 seconds for a CLI that ignores its signal, so a delete no longer judges what it would lose while a stopped CLI can still write in the worktree.
- **The daemon keeps the 50 sessions that ended last, and every one still working.** When one more ends, the session that ended first leaves the list and the window takes it out of its "Ask" section. A session of a deleted work item leaves the list with its work item, as before.
- **After an update, "Stop" does nothing until the daemon restarts.** A daemon of the build before this one ignores the stop, and its failed sessions show no error output. The status line already says when the daemon is of another build.
- **For a client of the daemon:** a new message `stopHeadless`, with `requestId` and `id`, stops a working headless session and is answered with `done`, or with `error` `no headless session <id>` for an id the daemon does not list. A session that is not working is left as it is. A new server message `headlessDropped`, with `id`, is sent to every client when the bound of 50 takes a session off the list. `HeadlessInfo` gains `errorOutput`, the last of what the agent's process printed on its error stream, and `stopped`, which reads `"limit"` or `"request"` for a session that was stopped and `null` otherwise. An archive, a delete and a repository's removal set `stopped` to `"request"` on the sessions they end.
