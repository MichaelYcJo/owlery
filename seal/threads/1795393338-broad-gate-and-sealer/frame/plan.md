**Constraints.**

- The daemon runs no Python (`docs/architecture.md` *What we take from AgenticSeal*). It reads and writes the two records in its own code, and the check's Python reads the same files on GitHub. The two spellings can drift.
- A sealer holds `Read`, `Glob`, `Grep` and `Bash`, and a command of it that asks for permission is refused. Whether `git diff` asks in the mode `default` was not run (`seal/threads/1795338000-role-tools-and-permissions/frame/questions.md` Q4). So the sealer's prompt carries the diff, as a round's does.
- One worktree does not hold two agents (`docs/architecture.md` *What a session survives*). The gate runs while no stage runs, and it reads at its start and at its end whether the worktree moved.
- The daemon exits when it holds no client, no live pane, no working session and no running chain (`daemon.ts:2484` `checkIdle`). What must be read after that is in a file.
- A chain that the store's guard refuses fails the guard of its whole file (`repositories.ts:85`, and `last-look.ts:136` for a look). A state or a field this work takes out of `Chain` stays among what the guard takes of a file (`frame/design.md` *Data & interfaces*).
- `daemon.ts:540` `close` waits for every chain's run. A gate's command is ended at the close, as each headless run is stopped there.
- No case and no probe starts a real `claude`, by the owner's rule of this run. A start of the built app goes through `apps/desktop/test/built-app.ts` `BuiltApp.start` with `OWLERY_BACKGROUND=1`.

**The failure scenario of the chosen approach.** In six months a repository's gate does not pass under the daemon and passes in the person's terminal. The command reads a variable the person's shell sets only for a terminal, or starts a watcher where it finds no terminal, or leaves a file that git does not ignore. Each gate then stops the chain, the person reads the output and has to change the repository's command or its ignore rules, and until then no branch of that repository is sealed. The second failure: a long suite runs again after each decision the orchestrator rules at the seal, because a decision's commit is no closing record, and a chain that ends in two rulings spends three runs of the suite. The third: a real sealer answers with a section the daemon's reader refuses, the session's usage is spent, and no verdict is written. The fourth: `pr-check/lib/fields.py` and `record-blocks.ts` drift, and the daemon commits a block the check refuses. Scenario 2 runs the check's Python over the chain's records in every run of the suite, which catches the drift for the shapes that case writes and for no other. The fifth: a fix pass whose record the daemon refused to commit leaves its crafter's commits on the branch with no `Seal-Built-By:` trailer, so the next seal's `built-by:` lacks that session, and so does the seal after a fix pass whose session reported no id. The sixth: a build of the release branch before this work stored a chain `reviewed`, and a guard that no longer took that state would read the whole store as empty. `frame/design.md` *Data & interfaces* has the guard take it, and scenario 21 holds that.

## Operational impact

- **No migration.** A chain an earlier build of the release branch stored with the state `reviewed` is read as no chain, with the rest of its file read as it stands, and the next `getSeal` reads the records.
- **No new dependency and no new environment variable.**
- **The protocol changes as `frame/design.md` *Data & interfaces* lists.** A window of an earlier build sends none of the new messages. A window of this build that meets a daemon without the kinds draws what that daemon sends.
- **The daemon runs the repository's broad gate command in the person's worktree, with the person's rights, with nobody asked at each run.** The command is the one the head commit's `config.json` holds. It runs with no terminal, so a command that needs one fails there.
- **The run folder gains `gate-output/`, with one file for each work item whose gate ran.** A delete of the work item removes its file.
- **The daemon makes more commits in a person's worktree, with the subjects `frame/design.md` *Data & interfaces* gives.** Each holds files of the work item's directory alone and runs the repository's hooks, and nothing is pushed. The commit that records a fix pass gains a second trailer.
