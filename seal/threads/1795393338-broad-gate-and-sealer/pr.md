| When the rounds end, the daemon runs the repository's broad gate command on the branch's head commit and commits the result as a record. Tests a person ran do not count | Once the rounds settle, the daemon runs the command that the repository's `config.json` names under `Broad gate`, as the head commit holds it. It runs in the work item's worktree through `/bin/sh`, with no terminal and with the `PATH` the person's login shell prints. It runs only where the worktree holds no change outside the work item's records, and it reads the head and the worktree again after the run. A run that exits with 0 appends one block to `trail/gate.md` and commits it, with `decisions.md` where the person wrote a word while the chain ran, since every stage's commit carries that file. No message of the window records a run, so a test the person ran counts for nothing. "Get a seal" is refused before any round where the repository names no command |
| A failed gate stops the chain, and the work item's inbox line says so with the command's output within reach | Any other end stops the chain and commits nothing. That covers another exit code, a signal, the limit of 60 minutes, "Stop", and a commit or a change that landed during the run. The work item's line moves under "Needs you" and says why, for example "The broad gate failed: the command exited with code 3." The work item's view lists the gate first under "Ask", with "Show output", which draws the last 262,144 characters the command printed. A second daemon on the same folder reads the same output. Its grant refuses every call that asks for permission, a write and a command among them. Its prompt names the gate's commit and base, the work item, the round records, the gate's record and the diff. Its answer is its run's section of `guarantee.md`, which the daemon appends below earlier runs and commits. The verdict block carries `target:` with the tree and the base, and the verdict. The work item, the gate and the rounds are read from the file's place, `trail/gate.md` and the round records beside it, so the block repeats none of them. At `sealed` the chain rests; at `withheld` it stops with the reason; at `undecided` an orchestrator session decides the question or parks it, and the third `undecided` verdict of one work item parks with no ruling asked |
