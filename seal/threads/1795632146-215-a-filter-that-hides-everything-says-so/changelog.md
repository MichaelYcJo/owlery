# Changelog: a filter that hides everything says so

Issue #215. A state chosen in the sidebar's filter, or a search typed above it, can leave no repository in the sidebar, for example once the last work item it showed is deleted. The sidebar then stood empty and said nothing, so it looked as if Owlery had removed the repository. The filter's icon told a narrowed sidebar from a full one by its ink alone, and a typed search did not change the icon at all.

- **An empty sidebar says why.** Where a filter or a search leaves no repository, the sidebar says so in their place and names what narrowed it, for example: `No work item stands under "Needs you", so the sidebar lists none of its 2 repositories.` With a search typed it says `No work item matches "logs"`, or `No work item under "Needs you" matches "logs"` where both narrow. With one repository it ends `so the sidebar does not list its repository.` No sentence stands where a repository is left, or where every repository is hidden, since the button under the sidebar already says how many are hidden.
- **One press shows every work item again.** Under the sentence stands "Show every work item". It chooses All in the filter, empties the search field and widens the list in front too. The keyboard goes to the first repository's row.
- **The filter's icon marks a narrowed sidebar by an edge as well as its ink.** While a state is chosen or a search is typed, the icon stands inside a thin edge in every theme. Pointing at it says what it shows, for example `Showing: Needs you, matching "logs"`.
- **For a contributor:** themes gain the token `--on-edge`, the edge an icon's button takes while what it turns on is on. `pnpm run screenshots` now also captures the sidebar that a filter leaves with no repository, as `<theme>-<appearance>-narrowed.png`.
