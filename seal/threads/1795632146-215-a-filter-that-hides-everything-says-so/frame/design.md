## Scope

In scope:

1. **The mark's words and its state, as one function of `view.ts`.** It takes what is typed and the state chosen, and answers whether the filter is on and what the control says to a pointer. It is on where a state other than "All" is chosen, or where a search is typed. It says `Showing: <label>`, and `Showing: <label>, matching "<query>"` where a search is typed, so a search alone reads `Showing: All, matching "logs"`.

## What the daemon could do beyond the issue

This work says in the window why the sidebar is empty. The owner's misreading went further: they took the empty sidebar for Owlery having removed the repository with the branch. The always-on daemon knows things the window does not keep. Each item below says what it costs and whether it is in this work's scope. None of them is in this work's scope; the orchestrator files issues for those it keeps.

- **A record of what Owlery removed.** The daemon performs every delete, archive and repository removal, and keeps no account of them once the lists change. A short log the daemon writes at each one, such as "Deleted Doomed: the branch owlery/doomed and its folder, 2026-11-25 23:40", read in the History screen, would have answered the owner's question "did Owlery remove the repository?" in one look, whatever the filter showed. It costs a file the daemon appends to and a section of a screen, and it changes `protocol.ts`. It is for an issue.
- **Telling a repository gone from disk from one the filter leaves out.** The daemon could check, at its own pace and only while a window is connected, that each repository's folder still stands, and send a mark for one that does not. The sidebar could then say that the repository's folder is gone, in place of listing it as if nothing happened. It costs one check of a folder per repository per round. It is for an issue, and it meets #227, which reads the worktrees on disk.
- **The worktrees the filter cannot see.** Once #227 lists worktrees made outside Owlery, the sentence of this work could count them too, so "none of its 2 repositories" does not hide a worktree a person made by hand. That is #227's to add, and *Overlap with the release* in `plan.md` names it.
- **A repository's work items by state, sent by the daemon.** The window counts these itself from the lists it holds, so the daemon adds nothing here. It is not worth an issue.
