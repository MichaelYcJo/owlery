**A gate record or a guarantee whose reader refuses any line gives nothing, wherever the refused block stands.** `frame/design.md` *Scope* item 2 says that "A block the reader refuses gives nothing", which leaves open a refused block before a block that reads. **The bound of `repository-file.ts` holds the two files that are read, and not the files that are only looked at.** *Scope* item 2 lists a file over the bound among what gives nothing. `trail/gate.md` and `guarantee.md` are read through `repositoryFileText`, which refuses a link, what is no plain file and a file over `REPOSITORY_FILE_BYTES`. `frame/design.md` and the round records are never read: the frame stands where `frame/design.md` is a plain file by `lstat`, and a round is a plain file of `trail/rounds` whose name is `round-<N>.md`. A large `frame/design.md` therefore still says the frame stands. Judged against `frame/design.md` *Scope* item 2 and `repository-file.ts`.

**Only the last part of a path is held to be no link.** `trail/rounds` that is a link holds no round, and `trail/gate.md`, `guarantee.md` and `frame/design.md` that are links give nothing. A folder above them that is a link, such as `trail` or `frame`, is followed. This is how `repositoryFileText` treats a path for `decisions.md` and `routing.md` (`repository-file.ts#repositoryFileText`, its docstring), so the work item's records are held to one rule. "No folder of the worktree" in *Scope* item 2 is read that way.
