**The step after each case departs from `frame/design.md` *Scope* item 6 in two ways.** The frame closes, after every case, each pane `openPane` opened in that case, on the premise that a case that passes closes its panes itself. That premise is false for one pair. The case "makes a path a pane printed a link only where a file or a folder stands at it…" opens a pane and leaves it open, and the next case, "shows a path's file in Finder…", reads that pane and closes it as `panes`. With the step as the frame states it, the Finder case failed with "the window never showed a link under the pointer on row 3", because the step had closed the pane it reads. That was the run of the whole file with the late replay of `frame/design.md` *Grounding*. So the step acts only after a case whose state is `fail`, and it closes every pane `openPane` opened that the daemon still holds, since a case that failed may hold a pane an earlier case handed it. After a case that passes, it does nothing, which is what the frame says it does then. The Vitest runner marks a case `fail` before it runs the `afterEach` hooks, in `@vitest/runner` 4.1.12's `runTest`. Read. In the run after the change, the Finder case passed. Executed. Judged against `frame/design.md` *Scope* item 6, its sentence "A case that passes closes its panes itself, as today, so the step then closes nothing", and the case's own code.

**`closeFromElsewhere` reads the panes the daemon holds from its `ready`.** The step has to know which noted panes the daemon still holds.
