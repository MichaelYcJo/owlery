6. **In a pane the session runs each stage and the command writes each record.** The session asks the command which stage is owed, starts the role the answer names as a subagent of the bundle with the prompt the answer gives, and hands the role's answer back to the command. The command runs the repository's broad gate itself and reads its exit. ## Data & interfaces

**The pane's command** (`hooks.ts#claudePaneCommand`): `exec claude --settings <file> [--plugin-dir <bundle> --append-system-prompt-file <head>] [--continue]`. The bracketed part is given where the pane carries the chain. `paneCommands` takes one more argument, a function from a pane's folder to what the pane carries, so `hooks.ts` reads no repository itself.

**The pane's environment** where it carries the chain: `OWLERY_CHAIN`, the launcher's absolute path, and `OWLERY_BASE`, the work item's base as `chain.ts#roundBase` gives it.

**The pane's settings file**: `claude-hooks.json` as today, and a second file of the run folder for a pane under the choice "Owlery's chain", which holds the same hooks and `enabledPlugins`. The daemon writes the second file before each such launch, from the person's files as they then stand.

**The chain command**, run in a worktree. Each subcommand prints one JSON object on its first line and exits with 0, or prints a sentence and exits with 1 and commits nothing.

| Subcommand | Does |
|---|---|
| `owed [--base <base>]` | Reads the records at the head and prints the step `chain.ts#stepOwed` owes: `start`, `round`, `fix-pass`, `gate`, `seal`, `sealed` or `parked`.
