# Changelog: a Claude Code pane carries the owl chain

Issue #181. A branch you drove in a pane got its seal from the button "Get a seal" on its work item. The daemon then ran the review rounds, the broad gate and the sealer as sessions of its own, beside the pane you worked in. The pane's own Claude Code session was the CLI as it is, so it knew nothing of Owlery's process. In the button's first real runs it was refused twice before any round ran, and on a branch that had moved to another base the round would have read the wrong range.

- **A Claude Code pane carries the owl chain where the repository's pull request check is Owlery's.** The owl chain is Owlery's own chain: the roles of its bundle, which review a branch, fix what the review found and give the verdict. Owlery loads the bundle into that pane's session alone and adds a short note to the session's system prompt. The session then takes the branch it built through the review rounds, the repository's broad gate and the sealer before it opens the pull request. It starts each role as a subagent, such as `owlery:proofer`, and the skill `owlery:seal` says how. A shell pane, another agent's pane and a Claude Code pane of any other repository are launched as before.
- **Owlery's code keeps the order and writes each record, in a pane as in the daemon.** The pane's environment names a command in `OWLERY_CHAIN`. The session asks it which step is owed and hands it each role's answer, and the command commits the round's record, runs the broad gate itself and writes the verdict. A session cannot type a verdict, and its word that the gate passed is no gate. The window and the check `seal` read a seal from a pane as they read any other.
- **Your Claude Code settings are not written.** The bundle and every setting of a pane reach `claude` on its command line, from files in Owlery's own folder. Your plugins and skills stay beside the bundle. The first call of the chain command in a session asks you for permission, as any command does.
- **Where your Claude Code enables the AgenticSeal plugin in such a repository, Owlery asks once which chain the repository's Claude Code panes run.** One chain seals a repository. The dialog offers the owl chain, under which the plugin is off in that pane alone, and the AgenticSeal plugin, under which the pane carries nothing of Owlery's. Owlery keeps the answer for the repository, and "Claude Code panes run" in the repository's settings shows and changes it. Where you turn the plugin off, the pane carries the owl chain whatever answer is kept.
- **"Get a seal" is gone.** The seal's place at the foot of a work item's view shows the seal and why it broke, and holds nothing to press. The daemon's own chain stays for an issue you hand over, which release 0.0.5 brings (#55). Nothing in the window starts it in this release.
- **A chain follows the base its first round recorded, and a branch that left its base is refused.** The refusal names the commit or the base and says how to name another, which is `--base` on the chain command.
- **Under `Automation` `yes` a pane's session does not stop its run with a question.** A hook of the bundle refuses the question. The session goes on with the question's default and writes the question into the work item's `frame/questions.md`. A question that opens with `No default can be taken: ` and a reason still reaches you.
- **The back of a seal from a pane says that its stages ran outside the daemon, and shows no cost of them.** Owlery reads no cost of a pane's session. The pull request's body says the same.
- **What this release does not cover.** A pane's chain starts at the review rounds, on what the session built: design and implementation as stages come with handing over an issue (#54, #55). Another agent's pane and a repository with no check of Owlery's get no seal from a pane. A pane's usage is first read in release 0.1.0 (#73). No agent has run a whole chain in a real pane from its first step to a seal: short real sessions showed the bundle's agents, its skill, the note, the refused question and the plugin kept out, and the owner's walk (#184), which moved to release 0.0.4, is the first whole run. A worktree whose branch adds Owlery's check to a repository that has none is asked nothing until that branch merges.
- **For a client of the daemon:** the message `getSeal` is gone. A repository carries `chain`, with `owl`, `plugin` and `chosen`, and `setRepository` takes `paneChain`. A daemon of an earlier build sends no `chain`, and the window then asks nothing.
- **For a person who builds Owlery:** `pnpm run pane:run` starts a real pane on the owl chain in short sessions of your own `claude`, once with no choice and once under the choice of the owl chain. `pnpm run screenshots` draws the chain choice's dialog and the repository's settings among its views, and starts no chain.
- **`docs/product.md`, `docs/architecture.md`, `docs/roadmap.md` and `docs/design.md` state the decision, in both editions.** The roadmap also states each release from 0.0.1 to 0.1.0 as the tracker holds it, and what the owl chain in a pane covers in release 0.0.3.
