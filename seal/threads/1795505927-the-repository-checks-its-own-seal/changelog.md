# Changelog: the repository checks its own seal

Issue #146. Owlery's own pull requests were checked by the AgenticSeal plugin's workflow, `hygiene.yml`, at a release of the plugin a person moved by hand. The plugin's check refuses the lines the owl chain writes into a verdict block, so the first pull request the owl chain sealed here would have failed it. Owlery's check was also named `Owlery seal`, which named the app where the seal comes from the owl chain, Owlery's chain of agents.

- **The pull request check is named `seal`.** The check the workflow posts on a pull request's head commit is `seal`, and the workflow's job is `records`, so the two bear two names. The seal section at the top of a pull request's body is headed `## Seal`, and the dialog "Records and check" names the check `seal`. A body an earlier build wrote is still read and rewritten, since Owlery reads the section by its two marker lines.
- **The check's title says when the owl chain gave the seal.** A seal reads "Sealed by the owl chain at" and the sealed commit, and a broken one "Seal of the owl chain broken: a commit landed after" and the sealed commit, where every verdict block the title names holds the `rules:` line the owl chain writes. A seal another tool gave, such as the AgenticSeal plugin's sealer, keeps "Sealed at" and "Seal broken: a commit landed after".
- **Owlery's own pull requests are checked by Owlery's workflow, and `hygiene.yml` is gone.** The repository's `.github/workflows/owlery-seal.yml` is the one Owlery writes for the app's version, and a case fails where the two differ, so the pull request that moves the version rewrites the file. Owlery's check still reads a work item's records in the form the AgenticSeal plugin's process writes, and reads no pull request body the plugin composes.
- **Owlery's own repository is on the owl chain.** A Claude Code pane of it carries the owl chain where your Claude Code does not enable the AgenticSeal plugin there. Where it does, the window asks once which chain the repository's Claude Code panes run.
- **A repository connected under release 0.0.2 keeps the workflow that release wrote.** That file fetches the check at `v0.0.2`, which posts the check under its earlier name, `Owlery seal`, and its job bears the id `seal`. Owlery rewrites no committed file. Replace `.github/workflows/owlery-seal.yml` with the one this release writes, and where a rule of the repository required the earlier check, require `seal` instead.
- **`README.md`, `docs/product.md`, `docs/architecture.md` and `docs/roadmap.md` state the new names, in both editions, and so does `pr-check/README.md`.** `docs/architecture.md` *Compatibility with AgenticSeal* says where the compatibility with the plugin's check ended.
