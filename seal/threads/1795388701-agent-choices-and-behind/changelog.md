# Changelog: the inbox says what an agent asks and how far a branch is behind its base

Issue #27. When an agent in a work item's pane asked the person a question, its line said "Working" until Claude Code sent a permission request or a notification, and then said "Asks to use AskUserQuestion" or the notification's sentence, never the question. A work item said how many commits its branch was ahead of its base branch, and not whether the base had moved on.

- **A work item whose agent asks you a question waits for you from the moment it asks, and its line says the question and the choices the agent offers.** The line stands under "Needs you" and reads, for example, "Which library formats the dates? date-fns · dayjs", followed by "(and 1 more question)" where the agent asks more than one. A work item parked with a question of its own records, or one whose "Ask" session waits for you to allow a call, still says that first. The question is read from Claude Code's call of its question tool, which its hook hands to Owlery before you answer, and never from what the pane prints. The shape of that call was read from Claude Code's hooks reference and from its 2.1.330 executable, and has not yet been seen from a real session.
- **The preview and the work item's view list the choices under the question.** The card "Claude Code asks" shows each question, and under it a numbered list of its choices, each with what the agent says it leads to. Under a question that takes more than one choice stand the words "More than one may be chosen." No choice is a button and the card holds no field: you answer in the agent's own pane, where Claude Code asks.
- **A work item says how far its branch is behind its base branch, beside how far ahead.** The preview says, for example, "6 commits ahead of main, 2 behind", and the view's facts say "main · 6 ahead · 2 behind". Behind is how many commits the base branch holds that the work item's branch does not, so you see that the base moved before you ask for a seal or merge. Both counts are read against the base as your clone holds it, and Owlery asks no remote for them: the count against a remote's branch moves when you fetch. A base that moved does not mark the work item as changed since you last looked.
- **After an update, the window shows no question's choices and no count behind until the daemon restarts.** A daemon started by the build before this one sends neither, so the line and the card say what they said before, and the preview says ahead alone. The status line already names a daemon of another build.
- **For a client of the daemon:** wherever the daemon sends a session, as in `ready` and `inbox`, and in the last look, the session carries `stateQuestions`: the questions the event that began its state asks, each with `asks`, `options` (each with `label` and `implies`) and `multiple`, or `null`. Each text holds 2,000 characters at most. Wherever the daemon sends a work item, and in the last look, the work item carries `behindBase`: how many commits its base branch holds that its branch does not, or `null` where `aheadOfBase` is `null`. A client of an earlier build reads the absence of either as `null`, and a look written before this build is still read. No message is added.
