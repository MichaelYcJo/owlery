# Phase 1: 1795046887-socket-path

## What this phase found

**The frame holds, except for one sentence of scenario 4.** `apps/desktop/src/daemon/hooks.ts` was opened at `522621d` and is as `frame/design.md` *Grounding* states it: the relay command at `:39`, `HookServer.listen` at `:96-108`, `close` at `:114-116`. `apps/desktop/src/daemon/main.ts:27` gives `listen` the path `join(runDir, "hooks.sock")`. The refused listen was reproduced before any code changed: the new case of scenario 1 failed with `listen EINVAL: invalid argument` at `src/daemon/hooks.ts:103`. Scenario 4 says the cases that exist at `56ce302` pass unchanged, and one cannot. It is the first departure below.

**What was built.** The fix is `d2df840`, and `10fedd8` after it changes one case alone. `HookServer.listen` and `HookServer.close` each run their one call of Node from inside the socket's folder and move the working directory back before they return. A private function `inside(dir, act)` in `hooks.ts` holds the move. The relay command is the one `frame/design.md` *Data & interfaces* gives, character for character. `socketPath` stays the whole path, and the mode is set by that whole path, which the system takes at any length: only the string given to `bind` and to `connect` is capped.

**What phase 2 needs.**

- A refused listen still rejects the promise `listen` returns. Where the socket's folder cannot be entered, or the daemon's own working directory cannot be read, the rejection now comes from the move and not from Node's `listen`, so its message is the move's. Phase 2's line in `daemon.log` is the error's message, whichever call it came from.
- `HookServer.listen` throws, and does not reject, where the path it is given holds something `rmSync` cannot remove. That line is unchanged: `if (existsSync(socketPath)) rmSync(socketPath);` runs before the promise is made. Inside `main`, which is `async`, a throw and a rejection reach the same place. `frame/questions.md` Q2 is still open, and this phase did not run it.
- `close` now rejects where the socket's folder is gone. `stop` in `src/daemon/main.ts` awaits `hooks.close()` before `process.exit(code)`, so a daemon whose run folder was removed under it would end through the unhandled rejection and not through its own exit code. `frame/design.md` *Scope* item 7 puts that daemon out of scope, and `gaps.md` *Not done* holds the item.

**Departures from the frame, each with its grounds.**

- *One assertion of an existing case changed.* "names no pane and no socket in the file, so one file serves every pane" expected the settings to contain the text `$OWLERY_HOOK_SOCKET`. The command of *Data & interfaces* writes the variable as `${OWLERY_HOOK_SOCKET%/*}` and `${OWLERY_HOOK_SOCKET##*/}`, and holds the earlier spelling nowhere, so the case failed against the frame's own command. The case now expects both of the new spellings. The alternative was a command that copies the variable into a second one to keep the old spelling, which would bend the probed command to an assertion about spelling. Judged against *Data & interfaces*, which gives the command "as probed", over scenario 4. Every other case that existed at `56ce302` passes with its body unchanged.
- *Scenario 2's refused listen has a second form.* The frame's refusal is a socket path whose folder does not exist. That refusal happens before the working directory moves, so its case cannot fail on the move back: with the move back removed it stayed green. The case runs both refusals: the absent folder, and a socket whose own name is over the cap in a folder that exists, where the listen is refused after the move. The second went red with the move back removed. The first still pins that the refusal is a rejection and that nothing moved.
- *The relay command has one case more than the frame names.* *Scope* item 3 says the command exits 0 and writes nothing where the folder is absent. A command that went on after a failed `cd` would hand the event to a socket of the same name in the session's own folder. The case "sends nothing, says nothing and lets the session go on when the socket's folder is gone" runs the command in a folder that holds a listening `hooks.sock`, with `OWLERY_HOOK_SOCKET` naming a folder that does not exist, and expects no event, no output and exit 0. The existing case "lets the session go on when Owlery is not listening" also expects no output now.
- *The cases' scratch folder is its real path.* `scratch()` in `test/hooks.test.ts` returns `realpathSync` of the folder it makes, so a case can compare a folder with `process.cwd()`. On macOS that puts `/private` in front of the path every case of the file uses. An `afterEach` moves the working directory back to where the file started, because two cases move it.
