# Changelog: the person's word is committed in time and tried again

Issue #150. When a person reverses a decision or answers a question, Owlery's background process writes the word into the work item's record and commits the record. That commit had three gaps. A repository hook that never ended held the commit, and with it every later commit of that worktree and the background process's own exit. A word written while an agent worked waited for the agent's own commit, which might never come. A commit that failed was not tried again, and nothing in the window said that the word was not committed. A word that stays out of every commit is missing from the record the pull request check and every other clone read.

- **Every commit Owlery's code makes ends within five minutes.** This covers the commit of a person's word, a stage's commit of the owl chain's records and the commit that sets up the place for work records. Git and the repository's hooks and signing run in a process group of their own, with no input. Past the limit Owlery ends that group, and the file stays written and not staged. Where the commit was made before the end, as under a `post-commit` hook that does not end, the commit stands. The error names the command and the limit: "git commit did not end in 300 seconds and was ended". A stage's commit that is ended stops the chain with that sentence, as a hook's refusal does.
- **Owlery's background process no longer waits without end for a commit when it stops.** It waits three seconds for a commit under way, then ends it, so "Restart Daemon…" and "Quit Owlery Completely…" are not held by a hook. The word stays in the record, and the next start finds it.
- **Owlery finds the words no commit holds from the repository itself.** A word is owed where the record in the work item's folder holds a reversed decision or an answered question that the record at the branch's newest commit does not hold. Owlery keeps no list of them, so a restart, an update or a closed window loses none.
- **A word written while a session works is committed once the session ends.** Owlery commits the record alone once no session of the work item is working and its chain is not running, within three seconds of the session's end, with or without a window open. Where a commit made in the meantime carried the word, Owlery makes none.
- **A commit that failed is tried again.** The next try comes a minute after the failure, and the wait doubles after each further failure, to an hour at most. A change of the record, or a new commit on the branch while a window is open, makes the next try due at once. The log holds one line for each new reason a try failed.
- **The window says where a word is not committed.** The preview and the work item's view hold one sentence above the decisions. While the word waits for a session it reads "The record holds a word of yours that no commit holds yet: a session of the work item is working. Owlery commits it once that has ended.", in the muted ink. Where its commit failed it reads "The record holds a word of yours that was not committed:", then the first line git printed, then "Owlery tries again.", in the ink of a failure. The inbox's line says "word not committed" after its count of the decisions, for a failed commit alone. A window of an earlier build ignores the new field, and a window of this build reads a background process of an earlier build as owing nothing.
- **For a contributor:** `pnpm run screenshots` now writes a reversal into the record of the parked work item and a `pre-commit` hook that refuses its commit, so the inbox's shot shows the line's "word not committed". The parked view's shot scrolls its right column until the decisions are the last thing in it, so it shows the sentence with the hook's line, where it used to open at the questions.
