# Changelog: a connected repository's pull request check follows the app

Issue #132. When a repository is first connected, Owlery commits `.github/workflows/owlery-seal.yml` into it, and that workflow fetches the pull request check of the Owlery release that wrote it. An update of the app left that version where it was. A repository then kept running an older check than the app's, and nothing in the window said so. Once a release's branch is deleted and no tag of that release exists, such a workflow cannot fetch its check at all.

- **A repository whose check is older than the app says so on its row.** Where the workflow in the repository's main checkout fetches the check of an older Owlery than the running app, the repository's row in the sidebar holds a button before its "+", such as "Check 0.0.4". Pointing at it says whose check it is, that it is older than the app, and that a press opens the commit that moves it.
- **The move is one commit the person reads first.** The button opens the dialog "Records and check". The dialog says which version the workflow fetches the check at and which version the commit moves it to. It shows the commit's branch, its subject, `chore: move the pull request check to Owlery <version>`, and the new workflow whole. Nothing is written until "Move and commit" is pressed. The commit holds the workflow alone, runs the repository's hooks, and is not pushed. Where the commit fails, the workflow is put back as it stood, and the dialog shows git's words, a hook's output among them.
- **The move is refused while the checkout does not hold the workflow as its commit does**, staged or not, with the sentence the first setup gives.
- **Before the move, the dialog names the work items whose records Owlery's readers refuse.** For each work item of the repository that has a branch and is not archived, Owlery reads its round records, its broad gate's run and its guarantee at the branch's head. It uses the readers that cases hold to the check's answers, and names each work item whose records they refuse, with the reader's sentence. The dialog says that none of the check's other arms were read, so the moved check may still refuse a pull request.
- **Nothing is offered** for a workflow whose version Owlery cannot read, such as one a person edited, for a version as new as the app's or newer, and for AgenticSeal's `hygiene.yml`.
- **A daemon of an earlier build sends none of this.** The row shows an older check once the daemon of the updated app runs.
- **For a contributor:** `pnpm run screenshots` now also captures the dialog of the records place moving the check, with the repository's row beside it, as `<theme>-<appearance>-check-move.png`.

The rewrite of `docs/architecture.md` and its Korean edition is left to the settle, which writes the operations of this work item's `frame/design.md` *Rule changes*. The form of the row's button and the new view of the screenshot run are written in both editions of `docs/design.md` by this work.
