# Changelog: each stage prompt names the work item's worktree by its absolute path

Issue #235. Each prompt the owl chain hands a role said that the role works "in this folder, which is the work item's worktree". A pane's subagent starts in its session's folder, and that folder may be another worktree of the repository: a session that made a worktree for the work and ran the chain command there handed its proofer a prompt that pointed at the pane's own worktree. The proofer then read another tree than the one under review, and a crafter would have committed its fixes on another branch.

- **Each stage prompt opens with the work item's worktree by the absolute path of its top, and says that every path below is from that top.** This holds for the round, the fix pass, the seal, the judgment of convergence and the ruling on a stage's questions. The paths a prompt lists stay relative to the worktree's top, so a finding's `location:` still matches the paths git prints. The prompts that ended with "read the files of this folder" now end with "read the files of that worktree".
- **The fix pass's prompt tells the crafter to make each fix in that worktree and commit it there with `git -C` and the worktree's path.** The path is quoted for the shell, so a worktree whose path holds a space or a quote gives a command that works as written.
- **The role bundle's proofer, sealer, crafter and orchestrator definitions say that a role works in the worktree its prompt names, reads every other path its prompt gives from that worktree's top, and that the folder its session starts in may be another worktree.** They no longer say that the folder the session starts in is the work item's worktree.
- **A role the daemon launches reads what it read before.** The daemon starts each role session in the work item's worktree, so the path the prompt names is that session's own folder.
