# Implementation Plan: 1795632147-216-the-window-reads-the-lists-again

## Technical context

The tree as read at `8c7eb798`.

The window and the daemon speak one WebSocket protocol (`apps/desktop/src/shared/protocol.ts`). The daemon sends the four lists whole in `ready`, at a hello (`daemon.ts:878`), and in `inbox`, to every client whenever one of the lists changes (`daemon.ts#broadcastInbox`, line 3807). Nothing a client sends after its hello asks for them. A request the window sends carries a `requestId` (`renderer/shared.ts:67`), and the daemon answers it with `done` or `error`, or with an answer of its own type.

The daemon reads the outside on timers while a client is connected: git every `commitPollMs` (`daemon.ts#scheduleCommitRead`, line 4026), and each open pull request every `PR_POLL_MS` or `PR_REST_POLL_MS` (`daemon.ts#scheduleWatch`, line 4047, and `github.ts:32-35`). A hello reads git at once, makes every watched pull request due, and reads the agent's notice again (`daemon.ts#accept`, lines 838 to 842, and `#greet`, line 871).

The window takes an `inbox` in `renderer.ts#takeLists` (line 1563), which notifies, drops the closed panes and draws through the hold (`draws.draw(drawLists)`, line 1595) that #242 added (`renderer/press.ts`). The sidebar's head is static HTML (`index.html:647-658`), wired in `sidebar.ts#initSidebar` and drawn in `sidebar.ts#showSidebar`. `renderer/press.ts` is the model for a renderer module that the unit project imports: it touches no page when it is imported, and `test/press.test.ts` drives it with stand-ins.

The cases this builds on: `daemon.test.ts`'s client helper and its describe "the watch of an open pull request" (line 7327), whose `watched` fixture (line 7339) holds a stand-in for `gh` that counts calls and can hang; and the built-app file `notification-click.test.ts`, which holds the bell's case, a repository with work items and an agent pane, and a second client of the daemon.

**What breaks in six months.** A later change adds a read to the hello and not to the method of *Scope* item 2, or the reverse, and a press then reads less than a connecting window does. The one method that both call is what keeps that from happening, and `## Removes` row 1 of `frame/design.md` takes out the second copy. The other failure is cost: each press spends one `gh` call for each watched pull request, so a person with many open pull requests who presses often spends GitHub's rate for the person's token. The second press sends nothing while the first is on its way, which bounds it at one round of calls for each answer.

## Operational impact

The protocol gains one client message, `readLists`, and one daemon option, `listsWaitMs`. A window of this build against a running daemon of an earlier build gets no answer to a press. After 15 s its status line says that the daemon did not answer, beside the notice it already shows for a daemon of another build, which names "Restart Daemon…" (`docs/architecture.md` *Overall layout*). No migration, no environment variable, no dependency and no move of the version.
