# Questions for the planner: heavy commands wait their turn (#134)

The owner reads this frame before it is built. Each row a person can answer is a product decision the owner could overturn. Its default is what `frame/design.md` states, and the build takes the default where the row stays open.

Judgments the ticket left open that the tree answered. Their grounds stand where each line points, and no row reopens them:

- Which clause the issue means by *What we keep within limits*: `frame/design.md` *Grounding*, the first row of the table.
- Whether issue #42 already built one gate at a time: `frame/design.md` *Grounding*, the first bullet of what the code holds.
- Where a repository names its heavy commands: `frame/design.md` *Grounding*, the row of *State lives in three places*.
- Whether the daemon stores the queue: `frame/design.md` *Grounding*, the row "The daemon runs a work item's review rounds and fix passes one stage at a time".
- Whether a hook can hold a command back by its text: `frame/plan.md` *Alternatives considered*, the row of the hook.
- Whether the daemon should run every heavy command itself: `frame/plan.md` *Alternatives considered*, the row "The daemon runs every heavy command itself".
- How a turn travels from a pane to the daemon: `frame/plan.md` *Alternatives considered*, the row of the WebSocket protocol.
- Whether naming two runs in a gate's record changes the records' grammar: `frame/design.md` *Grounding*, the row of *Records are committed to the repository*.
- Whether what a run took belongs in the ledger: `frame/plan.md` *Alternatives considered*, the row of the ledger.
- Who builds the reading of the machine, the store and the dialog: `frame/design.md` *Grounding*, the row of #32's frame.

One assumption that different answers would not change: the issue lists "the load the daemon reads" among what the default comes from. This frame reads the load for the second run of a gate and for what is kept and shown, and takes the default's number from the cores and the memory alone, since a default that moved with the load of the minute would be a different number at each look.
