**The frame holds for this phase, read against `fa40810`, with four statements the build did not follow.** Each unit `frame/design.md` *Data & interfaces* names stands by its name, and #40's module exports every function the frame calls. The four:

- **`unread` also holds the fences the reader names as not read.** *Scope* item 12 calls `unread` "the blocks the reader refused". #40's reader returns a second list, `notices`, for a fence that opens like a `seal` block and is not one. Such a fence is a block a person or a stage meant as a decision, and the reader read none of it. The daemon sends each notice with the refusals, in the order of the file, and decides nothing on either. Judged against *Scope* item 2 ("the daemon sends its line and the reader's reason") and `frame/plan.md` *Technical context*, the first failure, which asks that the loss is visible.
- **The store of the times writes in a function of its own, `flush`.** *Data & interfaces* gives `record-times.ts` one function that returns each block's `since`, and has the store write at each change. The daemon needs the times a read returns also where the write throws, and one pass reads every work item. `RecordTimes#since` holds the change in memory and returns the times, and `RecordTimes#flush` writes the file once where something changed. A write that throws is not tried again until the next change, so a run folder that cannot be written gives one line of the log for each change and not one for each pass.
- **The record is read by `Daemon#readRecord`, which the pass calls, and not inside `readBranch`.** *Data & interfaces* says "`readBranch` reads the record beside the branch". `readBranch` returns at once for a work item with no base commit and waits on git for every other. The pass reads every record first, without a wait, and then the branches. So a `ready` that goes out before git has answered carries the records, and a work item with no base commit has its record read.
- **Scenario 1's and scenario 5's "B holds none" is read with a directory in B's worktree.** The cases give both work items a directory, so B holds none because nothing was written for it, and not because it has no directory.

**Decisions made while building.** Each was judged against the document named.

- **The answers of an `answerQuestions` are held against the text the write is applied to.** The change `writeRecord` runs reads the open questions out of the text it is given, refuses the message there, and writes each answer. So the file is read once, and an answer cannot be written against a record that another writer changed between a read and the write. A message for a work item whose directory holds no record is refused with "Work item 3 waits for no answer.", and no file is made. Judged against *Scope* item 9.
- **An `answerQuestions` answers the open questions alone.** A record can hold answered questions beside open ones after a second park. The message carries one answer for each open question, and an id of an answered question or of a decision is refused with "Work item 1 holds no open question 9.". Judged against *Scope* item 9.
- **A work item with no directory answers a `reverseDecision` and an `answerQuestions` with "Work item 3 has no record of decisions."** *Scope* items 4 and 9 name no such case, and both methods refuse the same work item.
- **`Daemon#decided` refuses a `by` that is empty or no text**, as `Daemon#park` refuses an asker that is. `by` left out, or null, writes no `by:` line. Judged against *Scope* items 3 and 8 and the list under *Data & interfaces* that the orchestrator folded.
- **Each refusal of the two methods comes before the record's writer is asked.** A kind that is no `DecisionKind`, an empty text and a default that names no option would each also be refused by the writer's grammar, with a line in the log. The cases read the log as empty after the refusals, so the guards are what refuses.
- **A record that stands and cannot be read is one unread line.** A folder at the record's path, or a file the daemon may not read, gives the work item no decision, no question and one `unread` entry at line 1 that opens "the record cannot be read: ". A file that does not stand is a record of nothing. Judged against `frame/plan.md` *Technical context*, the first failure.
- **The daemon reads an archived work item's record at its restore too.** *Scope* item 2 names the archive and the daemon's start. The inbox that lists the work item as restored then carries what a stage wrote while it was archived, and the next pass would have read it at most three seconds later.
- **`Daemon#decided` and `Daemon#park` log a write that failed and return nothing.** The log reads "the record was not written: …". A write of `record-times.json` that fails logs "the times of the records were not written: …", and the daemon goes on with the times in memory.
- **A block's time is compared by the word of its state.** A decision that goes from `reversed` to `applied` gets a new time, and one whose message alone was edited by hand keeps its time.
