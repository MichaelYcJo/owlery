# Changelog: the rules of how work runs here live in the repository

Issue #323. Many rules for how work runs in this repository stood only in one machine's agent memory, so a session on another machine or a contributor's did not know them.

- **A `CLAUDE.md` at the repository's top holds the rules every session here follows.** Before each step of a work item the orchestrator reads the remote, and after each step it pushes the branch, so another session or machine can take the work over. A run held for another session leaves a `handoff.md` in each open work item. `routing.md` quotes the owner's delegation verbatim with its date. A framer's design says what the daemon could do beyond the issue, a comparison with another product inventories every surface a person touches, and a reported gap is filed, never answered with a workaround. The file links to the policy documents for every rule they hold.
- **The roadmap states four more tracker rules.** What a release holds is counted from its GitHub milestone, an issue labelled `owner runs` is the owner's alone, a decision that shapes an open issue goes into that issue's body, and the release note is built from the fragments as they stood before the settle removed them.
- **A choice only a study can raise is asked once the study's result stands**, not in the batch at the start (`docs/architecture.md`).
- **An icon candidate is judged at the Dock's size, and a brand name is searched against written criteria** (`docs/name.md`).
