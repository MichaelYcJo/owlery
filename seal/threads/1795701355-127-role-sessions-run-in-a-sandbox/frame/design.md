## Scope

In:

1. **Each grant names where its commands write.** `RoleGrant` gains `commands: "worktree" | "scratch" | "nowhere"`. The crafter at a fix pass: `worktree`. The proofer at a round and the sealer at the seal: `scratch`. The orchestrator at a judgment: `nowhere`. The grant stays neutral, in `role-grants.ts`, and names no vendor's option.
2. **#39's command rule is lifted for the proofer and the sealer.** Their grants become `runs: true`, so `verdictOn` allows their commands as it allows the crafter's. The orchestrator keeps `runs: false`, and its commands that ask are refused with the rule `no-command` as today.
3. **Every role session the daemon launches runs its commands in the operating system's sandbox, through Claude Code's own.** The Claude adapter adds to the `--settings` value it already passes: `sandbox.enabled: true`, `failIfUnavailable: true`, `allowUnsandboxedCommands: false`, `autoAllowBashIfSandboxed: false`, `filesystem.allowWrite` and `filesystem.denyWrite` from the places of item 4, and `network` `{ strictAllowlist: true, allowedDomains: [], allowLocalBinding: true }`. The refresh launch holds no tool and is unchanged.
4. **The places, as absolute paths the daemon resolves.** A crafter's commands write in the worktree and the repository's git common dir (`git -C <worktree> rev-parse --path-format=absolute --git-common-dir`), and are refused that dir's `hooks` and `config`, so a commit is made and no hook that would run outside the sandbox is planted. A proofer's and a sealer's commands write in the session's scratch folder alone, and are refused the worktree. The orchestrator's commands are refused the worktree and are given no place. Every role is refused the role bundle's folder. Each refused place is a `denyWrite` entry, so the bound holds whatever Claude Code lets a command write by default in the working directory and the `--add-dir` folders (`frame/questions.md` Q3).
5. **The daemon makes each proofer's and sealer's session a scratch folder of its own.** It is `scratch/<headless session id>/` of the daemon's run folder, mode 0700, made before the launch, or a folder made under the system's temporary folder where the daemon has no run folder. The adapter is given it, adds it to `--add-dir` so the session's `Read`, `Glob` and `Grep` reach it, and lets the session's commands write there. The daemon removes it once the session's process has exited, or where the adapter's start rejected (`frame/questions.md` Q2).
6. **The adapter contract carries the bound.** `RoleAdapter.start` takes the places of item 4 and the scratch folder; its doc says an adapter that launches a role bounds the session's commands to them, or rejects the start with a sentence a person reads. The fake adapter records what it was given.
7. **What a role is told.** The session head of `claude-roles.ts#rulesHead` says that the session's commands run in the operating system's sandbox and write only where its prompt names. `roundPrompt` and `sealPrompt` drop "run no command" and keep "write no file of that worktree". The daemon appends to the prompt of a session that has a scratch folder one paragraph: the folder's path, that a clone, a probe and what they print go there, that a write elsewhere is refused by the system, and that the folder is removed when the session ends. `convergencePrompt` and `rulingPrompt` keep their sentence. The pane head and the pane launch are unchanged.
8. **The bundle's proofer and sealer.** `proofer.md` *Job* and the paragraph **A round reads, and runs nothing.**, and `sealer.md` *Job*, are rewritten: in a role session of the daemon the role writes no file of the worktree, its commands run in the sandbox and write only in the scratch folder its prompt names, and a proofer clones and runs narrow tests there with a `## Probes` row for each; in a pane's session a command that asks waits for the person, as today.
9. **Runs that show the system refusing.** `test/role-session.test.ts`'s stand-in case runs per pair and gains the crafter. The stand-in's command:
   - for the proofer and the sealer, `git clone -q --no-local <worktree> <scratch>/clone && printf x >> <scratch>/clone/README.md && printf x >> <worktree>/README.md`;
   - for the crafter, `printf x >> <worktree>/README.md && git -C <worktree> commit -qam probe && printf x >> <kept>/outside.txt`, where `<kept>` is the case's own folder outside the worktree.

   The case asserts that the request reached the daemon and was allowed, that the tool result the stand-in received names `Operation not permitted`, the bytes of each file, and, after the proofer's and the sealer's runs, that `git status --porcelain` in the worktree prints nothing. `package.json` gains `role:refusal:crafter`. The three scripts run once each at the phase's close, never in the suite. What the proofer's run prints is what the third cell of the `## Rule changes` table row states; where it differs, the phase record says so and the framer folds the cell.

Out, each with the issue the orchestrator files:

- **Where a command's network reaches, per role.** Item 3 lets a sandboxed command reach no host but the loopback, which tests that start a local server need. An allowlist per role, a package registry or GitHub for the crafter, is a product choice (`frame/questions.md` Q1) and an issue of its own: "a role session's commands reach no host, so a fix pass cannot install a package".
- **What a command reads.** The sandbox bounds writes; a command can still read the person's files outside the worktree, such as `~/.ssh` or a cloud CLI's credentials, and the network bound alone keeps it from sending them. An issue: "a role session's commands can read the person's credential files".
- **A pane's subagent roles.** A proofer or a sealer started as a subagent of the person's own Claude Code pane is answered by the person's permission settings, and its commands run in whatever sandbox those settings set. An issue: "a pane's owl-chain roles are bounded only by the person's own settings".
- **The crafter's writes in the git common dir.** Item 4 lets a crafter's commands write any ref and object of the repository, other branches' among them. An issue: "a crafter's commands can move refs of branches other than its work item's".
- **A proofer's tests that need installed dependencies.** A clone in the scratch folder has no `node_modules`, and installing them needs the network or a writable package store. That Owlery's own suite runs in a proofer's clone is not claimed. An issue: "a proofer's clone cannot install a repository's dependencies".
- **Other platforms.** macOS alone is supported. On a platform where Claude Code's sandbox cannot start, item 3's `failIfUnavailable` fails every role launch; *Platforms and their order* defers them.

## Data & interfaces

- `role-grants.ts`: `RoleGrant` is `{ writes: "worktree" | "nowhere"; runs: boolean; commands: "worktree" | "scratch" | "nowhere" }`. `GRANTS`: `proofer at round` `{ writes: "nowhere", runs: true, commands: "scratch" }`, `crafter at fix-pass` `{ writes: "worktree", runs: true, commands: "worktree" }`, `sealer at seal` `{ writes: "nowhere", runs: true, commands: "scratch" }`, `orchestrator at judgment` `{ writes: "nowhere", runs: false, commands: "nowhere" }`. `verdictOn` keeps its shape.
- `adapters/adapter.ts`: `RoleAdapter.start`'s options gain `commands?: { write: readonly string[]; refuse: readonly string[] }` and `scratch?: string`. The daemon gives `commands` with every `role` and never with `refresh`, and `scratch` exactly where the grant's `commands` is `scratch`. `write` and `refuse` are absolute folders the daemon resolved from the grant (*Scope* item 4); the adapter adds its own bundle's folder to `refuse`.
- `adapters/claude.ts#claudeArgs`: the role launch's object gains `sandbox: { allowWrite: string[]; denyWrite: string[] }` and `scratch: string | null`. The `--settings` value becomes `{"disableAllHooks":true,"autoMemoryEnabled":false,"sandbox":{"enabled":true,"failIfUnavailable":true,"allowUnsandboxedCommands":false,"autoAllowBashIfSandboxed":false,"filesystem":{"allowWrite":[…],"denyWrite":[…]},"network":{"strictAllowlist":true,"allowedDomains":[],"allowLocalBinding":true}}}`. `--add-dir` stays last, followed by `cwd`, the bundle, and the scratch folder where there is one.
- `daemon.ts`: `HeadlessSession` gains `scratch: string | null`. The daemon makes the folder in `beginHeadless`, resolves the places in `startHeadless`, appends the scratch paragraph to the prompt the adapter is given, and removes the folder on the session's `exit` event or where the adapter's start rejected. The run folder gains the subfolder `scratch/`.
- `chain.ts`: `roundPrompt` and `sealPrompt` change their last instruction (*Scope* item 7); `chain.test.ts`'s pins follow.
- `role-bundle/agents/proofer.md`, `role-bundle/agents/sealer.md`: the text of *Scope* item 8.
- `test/role-session.test.ts`, `package.json`: the stand-in case per pair and the script `role:refusal:crafter` (*Scope* item 9).
