- **Whether the repository holds the sealed commit, and whether the head holds it, are read before the order's function.** Scenario 8 asks `broken` for a seal whose commit the head does not hold, whatever else the records say, and *Scope* item 9 has the check's guarantee arm refuse where HEAD does not descend from the sealed commit. `stepOwed` answers `sealed` only where the newest verdict seals the gate's commit, so this condition decides alone only for a history whose trees are equal after a rewrite. The two reads also keep `pathsBetween` from running on a name git does not hold. Judged against `frame/design.md` *Scope* items 3, 4 and 9, and scenario 8.
- **The order of the sentence's causes.** No commit of the seal's name, then a head that does not hold it, then a record that does not read (`ChainStop`), then the first path that is no closing record and differs between the sealed commit and the head, then the step the order owes. Judged against `frame/design.md` *Scope* item 4.

A seal is not shown broken where git failed and the records did not. Judged against `frame/design.md` *Data & interfaces*, the sentence on `WorkItem.seal`.
- **The sentence is cut at 2,000 characters by the daemon's own `cutText`.** A sentence grows past that where a `ChainStop` quotes a line the reader refuses (`record-blocks.ts#blockAt`). `daemon.ts#sealAt` cuts it as `recordedOf` cuts a verdict's reason, so the daemon holds one cutter. - **`standingOf`'s new parameter has no default.** Each caller says where it reads `decisions.md`: `runChain` passes `worktree`, as before, and `sealAt` passes `head`. Judged against `frame/design.md` *Scope* item 2.
- **The chain's read of its branch waits for the read under way.** `runChain` calls `daemon.ts#readBranchNow` in its `finally`, so a chain that rests or stops is read without a wait of one interval. Two reads of one branch could otherwise end in the wrong order and keep an earlier head's reading. So `readBranchNow` starts after the pass that `readCommitsNow` runs, if one is under way. A pass that starts later reads the same head as the chain's read.
- **The records a case commits are shared.** `test/chain-run.ts#commitSeal` commits the routing, round 1, the gate's run and a seal, each in a commit of its own, through `seal-records.ts#gateText` and `#guaranteeText`, and `#guaranteeWith` writes one run more. `test/seal-state.test.ts`, `test/daemon.test.ts` and `test/daemon-restart.test.ts` use both.
