**Decisions made while building, each with its grounds.**

- **`sealPrompt` takes `earlier`, with no default.** It is `{ run, commit }` of the seal the run follows, or null. Each caller says which: `runSeal` passes the value it reads, and the cases of the whole prompt pass null. Judged against `frame/design.md` *Data & interfaces*, "`sealPrompt` takes the earlier seal of *Scope* item 13", and phase 1's choice for `standingOf`'s parameter (`trail/phases/phase-1.md`).
- **The earlier run is the run before this one.** `runSeal` names it `step.run - 1`. `stepOwed` numbers the seal's run one more than the verdict blocks that stand, and the daemon writes one block for each run's section, so the newest block is the run before. Judged against `chain.ts#stepOwed` and `seal-records.ts#guaranteeText`.
- **The narrowed diff compares two trees.** `runSeal` calls `diffBetween(worktree, <sealed commit>, <gate's commit>, false)`, the two-dot form, which gives the paths that differ between the two commits and their diff. The sealed commit is an ancestor there, so the three-dot form would give the same. The closing records and the round records that changed since the seal are among the paths, since *Scope* item 13 asks for every path that differs. Judged against `frame/design.md` *Scope* item 13.
- **A newest verdict that is no seal gives the whole prompt.** *Scope* item 13 starts from "the newest verdict block at the stage's start is a seal". So a run after a broken seal and a `withheld` run gets the whole prompt again, since the newest block is the withheld one. The same holds where the repository holds no commit of the seal's name, since `sealCommit` is then null.
- **The words.** `frame/questions.md` Q3 leaves the wording to the build. The prompt gains one line under the issue's line, "- The seal this run follows: run `<N>` of `<directory>/guarantee.md` sealed `<commit, whole>`, and a commit after it broke that seal". The line above the paths reads "The branch changed these paths since the commit run `<N>` sealed:", or "The branch changed no path since the commit run `<N>` sealed." where none differs. The target line is unchanged. Each is pinned by the unit case named above.
- **The bundle's sentence is placed in the form's opening paragraph.** `docs/forms/the-guarantee.md` *The guarantee* says what the sealer verifies against, so the sentence on a run after a broken seal stands there, after "its order of work is `agents/sealer.md`'s".
