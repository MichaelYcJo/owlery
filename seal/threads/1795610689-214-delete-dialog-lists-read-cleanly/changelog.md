# Changelog: the delete dialog's lists read cleanly

Issue #214. The dialog that asks before a work item is deleted listed what the delete would lose in lists that were hard to read. A commit's hash ran into its subject, a long subject or path wrapped onto a second line, so the gaps between entries were uneven, and a list that scrolled could stop with a row cut in half. The section heads did not say how many entries each list held, and the sentence that says what the delete does stood in the same muted ink as a note.

- **Each commit stands on one row of two columns.** Its short hash stands in the fixed-width face and a muted ink, in a column as wide as the list's widest hash. Its subject follows on one line, cut with an ellipsis where it is longer than the row. Pointing at a row shows its whole subject.
- **Each path stands on one row in the fixed-width face.** This holds for the branch, the folder, the files with changes that are not committed, the untracked files and the ignored files and folders. A path longer than the row is cut with an ellipsis, and pointing at the row shows the whole path.
- **Every row has the same height, with no gap between rows.** So the entries of every list stand at one even spacing.
- **A list of more than ten entries shows ten and scrolls.** It comes to rest on whole rows, so no row is cut at its top or its foot. Every entry Owlery's background process listed can be read by scrolling. Where that process listed fewer entries than it counted, "and N more" stands under the list, as before.
- **Each section head says how many entries it holds.** For example: "39 commits no other branch, no remote and no tag holds", "1 untracked file", "14 ignored files and folders, which go with the folder". The head counts everything the delete would lose, the entries the list leaves out among them. The section that held "Removed from disk" now names what it holds: "The branch and the folder removed from disk", or the branch or the folder alone.
- **The opening sentence reads as the dialog's lead.** "A delete would lose the work named below." and the other sentences that open the dialog stand in the ink and the size of text that is read. "Nothing on a remote is removed." stays a muted note.
- **The dialog that removes a repository lists each work item's loss the same way**, where it deletes the repository's work items from disk.
- **For a contributor:** `pnpm run screenshots` now also captures the delete dialog of a work item whose branch holds 39 commits no other branch holds, as `<theme>-<appearance>-delete.png`.
