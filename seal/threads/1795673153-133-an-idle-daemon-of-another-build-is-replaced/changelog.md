# Changelog: an idle daemon of another build is replaced

Issue #133. Owlery's background process, the daemon, outlives the app. After an update, the window attached to the daemon the earlier build left, and the status line asked the person to choose "Restart Daemon…" even where that daemon ran nothing. A request the newer window sent that the older daemon did not know stayed open with no answer. Nothing recorded how a daemon ended, so nobody could count how often a restart or a crash cut a working agent.

- **At the window's load, an idle daemon of another build is replaced without a question.** Such a daemon runs nothing where it lists no live pane, no role session that works or waits for the machine, and no running chain. The app then stops it as "Restart Daemon…" stops one, starts the daemon of its own build, and the status line says nothing of another build.
- **A daemon of another build that runs something is kept.** Nothing in it ends, and the status line names "Restart Daemon…" as before. A daemon whose lists the app cannot read is kept too. An app replaces a daemon of one build once while it runs. Where it finds that build's daemon again, another app of that build shares the run folder, so the daemon is kept.
- **A daemon refuses at once a request it does not know.** The window then says "Owlery's background process is from another build and does not know this request. Choose "Restart Daemon…" from the menu to replace it." where it shows that request's refusal.
- **Against a daemon of a build before that refusal, the window ends a request after 10 seconds with no answer.** It says "Owlery's background process is from another build and has not answered. Choose "Restart Daemon…" from the menu to replace it." where it shows that request's refusal. A press of the sidebar's refresh button ends this way against such a daemon, before the button's own 15-second wait. The creation of a work item has no such wait: every earlier daemon answers it, after work that can take longer, so the Create button stays off until the answer and a second press cannot make a second work item. Against a daemon of this build or a later one, no request has this wait.
- **The daemon's log says how each daemon ended.** `daemon.log` in the daemon's run folder gains a line when the daemon stops: `owlery daemon <pid> stopped at <time>: <cause>, panes alive <n>, agents working <m>`. The cause is `signal SIGTERM`, `signal SIGINT`, `idle` or `error`. A daemon that starts where the one before it ended without stopping, because it was killed or the Mac lost power, writes `owlery daemon <pid> started at <time> after daemon <pid> ended without stopping`. The lines hold counts and no prompt, path or title.
- **For a contributor:** `ready` gains `answersUnknown: true`, and `error` gains `unknown: true` where the daemon does not know the request's type, with a `message` that names the type. A client of an earlier build ignores both. The window's waits are `answerWaits` in `apps/desktop/src/renderer/view.ts`, which `send` and `onMessage` tell of each request and each answer.
