Part of #41. The issue closes when `release/v0.0.2` reaches `main`.

Before this work the daemon could launch one role session when a client asked for it, and nothing ran a review on a branch. No control started one, nothing ordered the review rounds and the fix passes, no orchestrator was asked whether the rounds were converging, and no record of a round reached the repository.

| Done when | What holds now |
|---|---|
| Pressing "Get a seal" on a work item whose branch has commits starts the review rounds, and the person can close the window while they run | A work item's view has a "Get a seal" button at its foot, beside the seal's place. A press starts the rounds on a branch that holds a commit after its base, in a repository that holds the place for work records, while no agent of the work item is working and none of its questions is open. Otherwise the reason stands under the button and nothing starts. The daemon runs the rounds with no window connected, does not exit between two stages, and keeps the Mac awake through them where the person chose "While an agent works" |
| Each round is a fresh proofer session that reads files only, and its round record is committed to the repository in the format the PR check reads | Each round launches a new proofer session in the work item's worktree. Every call it asks permission for, to write a file or to run a command, is refused and counted. Its answer is the round record. Owlery writes that answer unchanged and commits it on the branch, after it has read the record's form and found the round's target in it. The pull request check holds a few rules the daemon does not, such as a confirmation that names a finding the earlier record lacks, so such a record is refused at the pull request and not before. The check passes the records a chain of two rounds and one fix pass leaves. Every proofer in the tests is a stand-in. Whether a real proofer answers in this form has not been seen, and the first chain on a branch of Owlery's own will show it |
| A round with findings is followed by a crafter fix pass, and every commit of a fix pass is read by a later round before the chain moves on | A round that leaves a finding open is followed by a crafter session that commits its fixes and marks each finding it answered. Owlery then commits the round record. The next round reads the commits made since the last round, and the rounds settle only when the last round leaves nothing open and no commit after it has gone unread |
| The daemon's code runs the order. The judgment whether the rounds are converging is asked of the orchestrator agent, and its answer is recorded | The daemon reads which stage comes next from the committed records and the branch alone, before every stage. Where round 2 or a later round leaves a finding open, the daemon asks an orchestrator session before the fix pass whether the rounds are converging. The answer is committed among the decisions made without asking, and a no stops the rounds until the person presses again. From round 6 on, the rounds stop for the person without that question. Six is the default this work item took for a question the owner has not answered yet. The question is not asked before a fix pass that only takes in decisions the person reversed, nor before a second fix pass on one round's record. One case does not fully hold: where the rounds are cut between the orchestrator's ruling on a stage's question and the convergence question that comes next, the person's next press runs that fix pass with no convergence judgment |
| Each role session's process is ended when its stage finishes | When a stage ends, the daemon stops the session and waits for its process to exit before it reads the stage's work or starts the next stage. A case of the tests holds this for every stage of a chain. Whether a tool's process that a real crafter starts also ends with the stage waits for a real fix pass |
| A stage that fails or is stopped leaves the work item in a state the inbox names, and the person can start the chain again from the records | A stage that fails, reaches its time limit or is stopped stops the rounds of its own work item and no other. The line moves under "Needs you", its second row says which stage stopped and why, and a notification is raised. Where the daemon ended during a stage, the rounds read as stopped at its next start. The next press of "Get a seal" goes on from the committed records |
