**Decisions made while building, each with its grounds.**

- **`stepOwed` is a function of a value, `Standing`, and `chain.ts#standingOf` gathers the value.** *Scope* item 4 asks for a function of the records and git that holds no state. `standingOf` reads each round record as the branch's head holds it and `decisions.md` as the worktree holds it. A round reads a committed tree, so a close block that only the worktree holds leaves its finding open, and the fix pass that follows is held to the committed record. `decisions.md` is read as the daemon reads it everywhere else, committed or not, so an answer a person just gave counts.
- **The fix pass's record is read against the record at the commit the pass started from.** A crafter that commits the record itself then changes nothing of what the daemon checks, and the daemon's own commit finds nothing left to carry.
- **A target line carries the whole commit hash.** The daemon compares the record's `target:` value with the text its prompt gave, and a shortened hash is another text.
- **Round 1's diff is read from the commit the branch and its base branch last shared, and against `baseCommit` where the base branch names no commit.** A base that gained commits since the cut would otherwise read as removals in the round's diff. The target line still names `baseBranch`, as *Scope* item 5 states it.
- **The routing a first start writes is answered on the day of the machine's own time zone**, the day the person pressed the button. The directory's slug is `work-item` where the branch's last part leaves none. A directory of that name that stands already stops the chain, and nothing is written over it.
- **A start waits behind the creations, the renames of a branch and the deletes, and for a commit of a person's word that is under way in the worktree.** The chain finds its directory by the branch's name and commits in the worktree. Each commit of a chain runs in the worktree's queue of commits, `Daemon#inWorktree`, so it never runs beside the commit of a person's word.
- **A person's word is written and not committed while the work item's chain is running, between two stages too.** `Daemon#commitWord` reads the chain beside the working sessions, and the next stage's commit carries `decisions.md` where it stands, as *Scope* item 17 has a stage's commit carry it.
