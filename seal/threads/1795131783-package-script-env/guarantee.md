## Observations, outside the verdict

- **Weighed, a user's own `node_modules` folder, `NODE` and `NODE_PATH`** (`executed` for the profile case, `read` for the rest): what the user's profile sets comes back, since the pane's login shell reads the profile after the filter. What is lost is a value set only outside the profile, in the launching terminal by hand, by direnv or by `launchctl setenv`. That is the rule `pty.ts:16-17` already states for the variables dropped before this change, and the issue's first bullet asks for no `PATH` folder inside a `node_modules` folder without exception, so it is the owner's decision, not a defect.
- **A headless session is not a pane, and the change does not reach it** (`read`, answered by the owner, whether it is a new issue): `adapters/claude.ts:133-136` asks the login shell for `claude` and `PATH` with the daemon's own environment, `npm_config_prefix` among it for an app started by pnpm, and `claudeEnv` (`:44-51`) gives the headless `claude` that shell's `PATH`. No party claims headless sessions, and issue #87 names panes alone.
