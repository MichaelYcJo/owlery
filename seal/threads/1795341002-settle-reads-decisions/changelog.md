# Changelog: the release's settle keeps each record that holds a reversal or an open question

Issue #131. A work item's `decisions.md` holds the decisions made for it without asking you, and the questions it was parked with. A decision you reversed and a question nobody answered are open rows of that record. A release's records were cleared by AgenticSeal's `seal settle --apply`, which does not read `decisions.md`. So it removed a work item's directory even where it held a reversal nobody took in. Nothing listed the release's decisions made without asking for its pull request and note either.

- **`pnpm --filter @owlery/desktop run settle` reads every work item's `decisions.md` in the repository.** It reads each file with the daemon's own reader, whether or not the file is committed. It names each directory it keeps and each row that keeps it, as `kept seal/threads/<id>/` followed by lines such as `seal/threads/<id>/decisions.md:9: decision 1 is reversed; decided: …; reversal: …`. It keeps a directory for a `reversed` decision, an `open` question, and a block the reader cannot read. A line the reader names as a notice is printed and keeps nothing.
- **The run exits 1 where it keeps a directory and 0 where it keeps none.** It exits 2 where it cannot read the records: a `decisions.md` that cannot be opened, or a `--since` ref that git cannot resolve. It writes nothing in either case. A repository without a records root prints `The repository holds no records root.` and exits 0.
- **It lists the decisions made without asking in the release.** The release's work items are the directories that the previous release's tag does not hold. That tag is the newest `v` tag reachable from `HEAD`, and `--since <ref>` names another. The list opens with one line per kind of decision, counting its decisions and those you reversed. Then each work item has a heading with its pull request where the commit that added its `routing.md` names one, and each decision gives its kind, what was decided, its grounds, who decided where the record says, and its state.
- **`--list` prints the list alone, as Markdown, for the release's pull request and its note.** It exits 0 whatever the settle keeps.
- **`--apply` runs AgenticSeal's settle and puts back each directory it kept.** It runs `seal settle --apply`, passes `--released-at <ref>` where you give one, and prints what that command printed once it ends. It then puts back from `HEAD`, with `git checkout`, each kept directory that the settle removed or changed, and prints `put back seal/threads/<id>/` with the rows that kept it. Its last line counts what it put back.
- **`--apply` refuses before anything runs where a put-back could lose something.** It names each kept directory that differs from `HEAD`, because a kept directory is put back from `HEAD`: commit or undo its changes first. It refuses where no `seal` is found on the path. Each refusal is named, then `settle: --apply ran nothing.`, and the exit is 2.
- **`--apply` puts nothing back where `HEAD` moved while AgenticSeal's settle ran.** It names each kept directory as not put back and exits 2. A directory whose checkout fails is named as not put back, the next one goes on, and the exit is 2.
- **`--apply`'s exit is the worse of the two.** It is 2 where it refused, where `HEAD` moved, where a put-back failed, and where AgenticSeal's settle exited 2, with any code but 0 and 1, on a signal, or did not start. It is 1 where either kept a directory, and 0 otherwise.
- **`docs/roadmap.md` *Releases and the tracker* now names this command as the way a release's records are settled.** `docs/architecture.md` *Records are committed to the repository* says that a block the daemon cannot read is an open row too, and points at that procedure in place of a `git grep` of two states. Both Korean editions say the same.
- **A file that git ignores inside a kept directory is not put back.** AgenticSeal's settle removes it with the directory, and `HEAD` does not hold it.
- **For a contributor:** `test/settle.test.ts` runs the command in temporary repositories, with a stand-in script named `seal` on the path, and never reaches AgenticSeal's own `seal`. The case of `test/decision-record.test.ts` that ran the `git grep` the policy gave a settle is gone with it.
