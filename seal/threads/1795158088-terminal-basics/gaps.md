## Not done

Eight things were within reach and not taken.

- **The dialog stays open where the session stops working while it asks.** `frame/design.md` *Scope* item 8 closes the dialog where the daemon no longer lists the pane, and names no other change of the pane. "Close pane" then closes a pane that would no longer have asked, which is what the person pressed.
- **`test/fixtures/receiver.sh` was not changed to serve these cases.** `test/korean-input.test.ts` runs it, and a pane file per pane id would change what that case reads. The terminal basics cases have a stand-in of their own, `test/fixtures/basics-shell.sh`, which repeats the receiver's four lines.
- **`frame/questions.md` Q1 was not measured in phase 2.** `frame/plan.md` *Phases* row 2 lets the phase measure it where the orchestrator allows what a logged-in `claude` leaves, and the phase's spawn allows no real `claude`. The row of *Not verified* names the owner.
- **The drop's own default is not stopped, and the drag shows no cursor the window chose.** A mutant that left the default in place passed every case, the one that reads the window's page after a drop among them. Electron starts no navigation for a dropped file while `webPreferences.navigateOnDragDrop` is `false`, its default, and `main.ts#createWindow` does not set it. The guard of *Scope* item 1 is not the ground: no run has shown it acting on a drop, and the row of *Not verified* on that guard says what was tried. A line no case can see was not kept. The cursor a drag shows over a pane is the system's choice, and no case reads a cursor.
- **A press of the Command key by itself takes the card away, as any key does.** `frame/design.md` *Scope* item 13 has the card leave "at once at a key pressed in the pane", and the card's rows name clicks made with that key held. A person who reads "⌘ Click" and presses the key sees the card go before the click. The click still does what the row said. Keeping the card at a bare modifier key would depart from the item's words, so it was not built, and the hand-back names it as the owner's to decide.
- **The card has no code of its own for a dialog that opens.** *Scope* item 13 has the card leave when a dialog opens. Each dialog of the page opens at a key or at a press of the mouse outside the card, and either takes the card away first, so a line that hides the card at `showModal` is one no case can see. Phase 4's menu opens at a press of the right button, which is such a press.
- **A request for a line's paths that fails is not caught.** `work-item-view.ts#findsPaths` answers the terminal when the main process answers. `paths.ts#pathsOf` catches every error of the disk, so the request fails only where the main process is gone, and the window reloads then.
- **`links.ts#chooseOpener` was not given a second kind of opener.** `frame/design.md` *Data & interfaces* has it called once more, with Finder's two acts as its system opener. The disk is read before the act is chosen, and the program `OWLERY_OPENER` names has to stand in for either act, so `paths.ts#chooseFinder` calls it once for each act. `chooseOpener` itself is unchanged.
