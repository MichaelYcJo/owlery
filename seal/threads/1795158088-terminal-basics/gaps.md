- **The dialog stays open where the session stops working while it asks.** `frame/design.md` *Scope* item 8 closes the dialog where the daemon no longer lists the pane, and names no other change of the pane. - **`test/fixtures/receiver.sh` was not changed to serve these cases.** `test/korean-input.test.ts` runs it, and a pane file per pane id would change what that case reads. The terminal basics cases have a stand-in of their own, `test/fixtures/basics-shell.sh`, which repeats the receiver's four lines.
- **`frame/questions.md` Q1 was not measured in phase 2.** `frame/plan.md` *Phases* row 2 lets the phase measure it where the orchestrator allows what a logged-in `claude` leaves, and the phase's spawn allows no real `claude`. The row of *Not verified* names the owner.
- **The drop's own default is not stopped, and the drag shows no cursor the window chose.** A mutant that left the default in place passed every case, the one that reads the window's page after a drop among them. Electron starts no navigation for a dropped file while `webPreferences.navigateOnDragDrop` is `false`, its default, and `main.ts#createWindow` does not set it. The guard of *Scope* item 1 is not the ground: no run has shown it acting on a drop, and the row of *Not verified* on that guard says what was tried. A line no case can see was not kept. The cursor a drag shows over a pane is the system's choice, and no case reads a cursor.
- **The card has no code of its own for a dialog that opens.** *Scope* item 13 has the card leave when a dialog opens. Each dialog of the page opens at a key that is no modifier key pressed by itself, or at a press of the mouse outside the card, and either takes the card away first, so a line that hides the card at `showModal` is one no case can see. Phase 4's menu opens at a press of the right button, which is such a press.
- **A request for a line's paths that fails is not caught.** `work-item-view.ts#findsPaths` answers the terminal when the main process answers. `paths.ts#pathsOf` catches every error of the disk, so the request fails only where the main process is gone, and the window reloads then.
- **`links.ts#chooseOpener` was not given a second kind of opener.** `paths.ts#chooseFinder` calls it once for each of Finder's two acts, when `main.ts` loads. `paths.ts#showInFinder` chooses which act to call only after it has read the disk, so the program `OWLERY_OPENER` names has to stand in for either act. `chooseOpener` itself is unchanged.
- **A program's modes do not outlive "Clear Screen" once the pane leaves the stage.** `frame/design.md` *Scope* item 17 has the daemon forget everything the pane printed, and a pane that comes back onto the stage is drawn from the daemon's replay into a terminal that was reset (`view.ts#screenTurns`, `giveBack`). The sequences by which the program asked for pastes in brackets, for mouse reporting or for the alternate screen are among what was forgotten. Phase 4's probe saw it: after "Clear Screen", another tab and back, a paste reached the pane's process without its brackets, where it had them before the tab was left. In the window that cleared, the modes hold until then, which the case reads. Keeping them needs a `forget` that carries what the daemon keeps in place of the output, or a daemon that reads the sequences, and either changes the message *Scope* item 17 and *Data & interfaces* state. That is the framer's to decide, so the phase built the message as framed and the hand-back names the question.
- **A pane's menu stays open where its pane is closed from elsewhere while it is open.** *Scope* item 8 closes the dialog in that case, and item 16 says nothing of the menu. Its items then do nothing: the screen holds no pane, and `work-item-view.ts#menuAct` returns.
- **A link's card can show while a pane's menu is open.** The press that opens the menu takes the card away, as *Scope* item 13 asks. The pointer may then leave the menu for a link and rest there, and the card shows beside the menu. A press on a row of the card is a press outside the menu and closes it, so each still does what it says.
