# Changelog: a pane takes a dropped file, a click on a link or a path and Shift+Enter, and Cmd+W closes the pane in front

Issue #95. A pane lacked four things a terminal has. A file dropped on it typed nothing, a click on a URL did nothing, Shift+Enter was Enter, and Cmd+W closed the whole window with every pane in it.

- **Cmd+W closes the pane in front, and no longer the window.** Where no pane is in front, the key does nothing. Shift+Command+W closes the window, and "File / Close Window" shows that key. On macOS that close hides the window, as the next item says.
- **On macOS, closing the window hides it, and Owlery keeps running with its panes.** The red button and Shift+Command+W both hide it. A session that begins to wait while the window is hidden still raises its notification. A click on the Dock icon or on a notification shows the window again, and "Quit Owlery" ends the app. A hidden window frees no memory. An app started with `OWLERY_BACKGROUND=1`, and an app on another platform, closes its window as before.
- **Closing a pane whose agent is working asks first.** A press of the tab's "×" or Cmd+W opens a dialog that names the tab, with the keyboard on "Cancel". "Close pane" ends the session. Every other pane closes at the first press, as before. A shell pane never asks, whatever runs in it.
- **A file dropped on a pane types its path into that pane**, and the pane takes the keyboard. A space, a quote and every other character a shell reads is written with a backslash before it. Several files are typed with a space between them. A program that asked its terminal for bracketed paste receives the paths as one paste. An image that is on no disk, such as one dragged out of a browser, types nothing.
- **A URL in a pane opens in your browser at a click with the Command key held.** A click without the key does what it did. Only an `http` or `https` address opens. A link a program prints behind a name (the OSC 8 sequence) opens the same way, and the terminal no longer asks first.
- **A path in a pane is a link where a file or a folder stands at it.** The path is read from the root, from your home folder where it opens with `~/`, and otherwise from the work item's worktree. A line number after it, as in `src/a.ts:12`, is left out. A click with the Command key held shows a file selected in Finder and never opens it in an app. A folder is opened in Finder, except one whose name holds a dot and that is no checkout, such as an app's bundle: that one is shown selected. A path with a space in it, and a bare name with no slash, is no link.
- **The worktree of another work item opens that work item's view** at a click with the Command key held. With the Shift key held as well, the click opens the folder in Finder.
- **A link under the pointer shows a card.** It shows after a moment, under the link, or above it where the window has no room under it, with the whole address or path and a row for each thing you can do: "Open in browser" and "Copy link" for an address, "Show in Finder" and "Copy path" for a path, "Open work item" and "Open in Finder" for another work item's worktree. A row names the click that does the same, and a press of the row does it too. For a link behind a name the card says the address the name carries. The card leaves when the pointer does, at a click elsewhere and at a key. The Command, Shift, Control and Option keys pressed by themselves leave it as it is, so you can hold the key a row names and then click.
- **A press of the right button on a pane opens the pane's menu**, and so does a click with the Control key. It holds "Copy", "Paste", "Select All", "Clear Screen", "Reset Terminal" and "Close Pane", and the pane it opens on takes the keyboard. "Copy" is dimmed where nothing is selected. "Paste" hands the pane the clipboard's text as a paste. "Clear Screen" empties the pane but for the line the cursor is on. "Reset Terminal" also ends every mode a program set, such as mouse reporting, which helps after a program crashed and left the pane unusable. "Close Pane" asks first where the pane's agent is working, as the tab's "×" does. The arrow keys move through the menu, and Escape or a click elsewhere closes it. It also closes when its pane leaves the screen, as where a click on a notification opens another work item. While it is open the window reads none of its own keys.
- **A cleared pane stays cleared.** "Clear Screen" and "Reset Terminal" also have the daemon forget what the pane printed, so the old output is not drawn again when you come back to the pane. "Clear Screen" keeps the modes a program set, such as pastes in brackets and mouse reporting, so a program that asked for them still receives a paste as one paste after you come back. "Reset Terminal" keeps none. A daemon that an earlier build left running does not know the request: with it, the old output comes back at the next visit, until that daemon ends.
- **On a Mac, Command with the left arrow, the right arrow and Backspace edit the line**, in every kind of pane. They send Control+A, Control+E and Control+U. A shell reads the first two as the line's start and its end. Control+U deletes what stands before the cursor in bash, and the whole line in zsh, the shell macOS starts by default.
- **Shift+Enter sends a line feed, the byte Ctrl+J sends**, in every kind of pane. Claude Code reads it as a line break in the prompt. A shell reads it as Enter. Enter and Option+Enter send what they sent.
- **The app has its own menu.** It reads "Owlery" where it read the package's name, and holds no item on Cmd+K, Cmd+N or Cmd+W, which the window reads itself, and none on Command with the left arrow, the right arrow or Backspace, which a pane reads.
- **The window never leaves Owlery's own page, and no second window opens**, whatever a pane prints or a person drops on the window.
- **`OWLERY_OPENER` names a program that acts in place of your browser and of Finder.** Owlery runs it with the address, or with the path to show, as its one argument. An app started with `OWLERY_BACKGROUND=1` and without `OWLERY_OPENER` opens no address and shows nothing in Finder. It also keeps a clipboard of its own, so "Copy link" and "Copy path" there never replace what you copied. A test or an agent that starts the app therefore never opens your browser or Finder, and never touches your clipboard.
